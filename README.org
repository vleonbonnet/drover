#+TITLE: drover
#+OPTIONS: toc:nil

Drover gathers the sessions of your coding agents into one place in Emacs: which ones wait for you, which ones run, and which finished while you were elsewhere. It shows how many sessions need you in the mode line, takes you to the most urgent one, and lists every session in a dashboard from which you can open, answer, interrupt, archive or preview any of them.

Agent front ends plug in as backends. The first is [[https://github.com/vleonbonnet/opencode.el][opencode.el]], for [[https://opencode.ai/][OpenCode]] 2.

* Requirements

- Emacs 30.1, a Nerd Font for the status icons, [[https://github.com/magit/transient][transient]] for the menus, and [[https://github.com/magit/magit][magit-section]] for =drover-dashboard=.
- For OpenCode sessions, opencode.el with its =opencode-state= session registry.

* Installation

With elpaca or straight:

#+begin_src emacs-lisp
  (use-package drover
    :ensure (:host github :repo "vleonbonnet/drover")
    :hook (elpaca-after-init . drover-attention-mode)
    :bind ("C-'" . drover-dispatch))
#+end_src

The OpenCode backend loads with opencode.el. Its sessions come from opencode.el's registry, which follows the shared OpenCode service whether or not a session has a buffer; drover opens the service's event stream when it starts.

* Statuses

| Icon (Nerd Font)     | Status    | Meaning                                                 |
|----------------------+-----------+---------------------------------------------------------|
| =nf-md-help_circle=  | Needs you | A permission request or question waits for you          |
| =nf-fa-times_circle= | Failed    | A turn failed while you were not looking at the session |
| =nf-md-check_circle= | Done      | A turn ended while you were not looking at the session  |
| =nf-fa-refresh=      | Retrying  | The running turn waits to retry a failed request        |
| =nf-md-timer_sand=   | Working   | A turn runs                                             |
| =nf-fa-circle_o=     | Idle      | Nothing to do                                           |

=drover-status-glyphs= changes them; the icons need a Nerd Font.

The first three need you (=drover-attention-statuses=). Sessions are ranked by =drover-status-order=, and among those that need you the longest wait comes first. Whether you saw a finished turn is the backend's to know: OpenCode records it in the service, so a turn read in any client, the TUI, the desktop app or Emacs, is no longer Done.

Subagent sessions always show under their parent, indented. A parent goes where the most urgent session of its tree belongs, so one whose subagent waits for you is listed with the sessions that need you, the subagent beneath it. Subagents are hidden unless they need you or =drover-show-children= is set.

* Attention

=drover-attention-mode= shows one count per status that needs you in the mode line, one icon and count per status, and nothing when no session needs you. Its tooltip lists the sessions; clicking it runs =drover-next=, the right button =drover-select=.

- =drover-next= visits the most urgent session. Pressed again at once, it moves to the next one in the order of the first press, so a session changing status meanwhile does not reshuffle the round.
- =drover-select= picks any session with completion, grouped by status and annotated with its project, branch, age and what it waits for. With a prefix argument it opens the session in another window.
- =drover-mark-all-seen= marks every Done and Failed session seen after confirming how many (=drover-catch-up-statuses=); with a numeric prefix argument, only those that ended at least that many hours ago. Useful to start from a clean slate, or after a day away.

* Keys

Drover binds no global key. Its commands are gathered in one menu, =drover-dispatch=; bind it to a key you can reach from anywhere, for instance:

#+begin_src emacs-lisp
  (keymap-global-set "C-'" #'drover-dispatch)
#+end_src

or, with =use-package=, =:bind ("C-'" . drover-dispatch)=. The keys come in three sets, and no key belongs to two, so the menu holds them all: the global keys everywhere, the session keys in lists of sessions and in prompt buffers, the prompt keys in prompt buffers. What does not apply where you are is greyed out rather than hidden, so the menu never changes shape.

** Session keys

In every list of sessions (=drover-dashboard=, =drover-table=, =drover-sidebar=, and opencode.el's session lists) these keys act on the session at point directly; in a prompt buffer, such as an OpenCode session buffer, they act on its session through the menu.

| Key | Command                    | Action                                            |
|-----+----------------------------+---------------------------------------------------|
| =o= | =drover-open-other-window= | open it in another window                         |
| =A= | =drover-respond=           | answer its question or permission request         |
| =k= | =drover-interrupt=         | interrupt its turn, after confirmation            |
| =s= | =drover-mark-seen=         | mark its ended turn seen                          |
| =u= | =drover-open-parent=       | open its parent session                           |
| =c= | =drover-open-subagent=     | pick one of its subagent sessions and open it     |
| =r= | =drover-rename=            | rename it                                         |
| =x= | =drover-delete=            | delete it for good, after confirmation            |
| =z= | =drover-archive=           | archive it, after confirmation                    |
| =g= | =drover-refresh=           | refresh the list, or reload the session's buffer  |
| =l= | =drover-store-link=        | store an Org link to it                           |
| =+= | =drover-new-session=       | start a session in its directory                  |
| =v= | =drover-peek=              | preview where it stands, without opening (lists)  |
| =V= | =drover-follow-mode=       | preview each session as point reaches it (lists)  |
| =U= | =drover-toggle-subagents=  | show or hide subagent sessions (lists)            |
| =G= | =drover-group=             | choose how sessions are grouped (drover's views)  |
| =F= | =drover-filter=            | choose which sessions are listed (drover's views) |

=RET= opens the session at point, and the usual keys of each list stay: =n= and =p= move, =TAB= folds, =q= quits. In lists drover does not draw, =drover-session-keys-mode= adds these keys; the OpenCode backend turns it on in opencode.el's session lists.

** Prompt keys

In a prompt buffer, where you write to an agent, through the menu.

| Key     | Command                       | Action                                 |
|---------+-------------------------------+----------------------------------------|
| =RET=   | =drover-prompt-send=          | send the prompt                        |
| =S-RET= | =drover-prompt-schedule=      | schedule the prompt                    |
| =i=     | =drover-prompt-attach=        | attach the region, or a file or buffer |
| =/=     | =drover-prompt-slash=         | insert a slash command                 |
| =@=     | =drover-prompt-mention=       | mention a subagent                     |
| =t=     | =drover-prompt-revert=        | stage a revert of what follows point   |
| =T=     | =drover-prompt-revert-cancel= | cancel the staged revert               |
| =y=     | =drover-prompt-copy-block=    | copy the code block at point           |

** Global keys

Everywhere, through the menu.

| Key | Command                      | Action                                                         |
|-----+------------------------------+----------------------------------------------------------------|
| =j= | =drover-next=                | visit the most urgent session                                  |
| =b= | =drover-select=              | choose a session                                               |
| =p= | =opencode-select-project=    | list the sessions of an OpenCode project                       |
| =S= | =opencode-consult-sessions=  | search the OpenCode session buffers                            |
| =1= | =opencode=                   | list the sessions of the current project                       |
| =2= | =opencode-list-all-sessions= | list every OpenCode session                                    |
| =3= | =drover-dashboard=           | the dashboard                                                  |
| =4= | =drover-table=               | the table                                                      |
| =5= | =drover-sidebar=             | the sidebar                                                    |
| =a= | =drover-prompt-agent=        | choose the agent                                               |
| =m= | =drover-prompt-model=        | choose the model                                               |
| =e= | =drover-prompt-effort=       | choose the reasoning effort                                    |
| =d= | =drover-prompt-directory=    | move the session to another directory                          |
| =C= | =drover-compact=             | compact the conversation, or the session at point in a list    |
| =f= | =drover-fork=                | fork the conversation at point, or the whole session in a list |

The OpenCode entries come with the OpenCode backend. =a=, =m=, =e= and =d= act on the current prompt buffer, or on the one =drover-default-prompt-buffer-function= returns; =.= on the prompt buffer you visited last.

** Adding to the menu

Add your own commands with =transient-append-suffix= and =transient-insert-suffix=, placed relative to a key of the menu. The OpenCode backend inserts its lists before =3=; other natural places are after =b= (session pickers), after =5= (more views) and after =O= (more prompt commands):

#+begin_src emacs-lisp
  (transient-append-suffix 'drover-dispatch "b"
    '("\"" "Prompt" my-prompt-command))
#+end_src

=drover-dispatch-session=, =drover-dispatch-list-p=, =drover-dispatch-view-p= and =drover-dispatch-prompt-p= are predicates for the =:inapt-if-not= of such entries.

* Views

Three prototypes list every session; they share the session keys, and differ in layout. Every view lists the same sessions, grouped the same way:

- =G= groups sessions by status, by project, or not at all (=drover-group-by=).
- =F= filters them by project, by status, by last activity (today, the last 24 hours, 7 or 30 days, or any age such as =3d=), and by a text found in their title, summary, project or branch. An empty answer removes a filter; =c= in the menu clears them all. A subagent that matches shows under its parent, even while subagents are hidden.
- =U= shows or hides subagents.

** =drover-dashboard=

A Magit-style buffer of collapsible sections, in a proportional font (the face =drover-dashboard=) with columns aligned in pixels. =TAB= on a session shows its directory, agent and model, and every request it waits on. The Idle group starts collapsed (=drover-dashboard-collapsed-statuses=); what you collapse or expand survives refreshes.

** =drover-table=

One table with a column each for title, project, branch, age and what the session waits for; each title starts with its status icon. Subagents follow their parent, indented, whatever the sort. Each group starts with a heading row; =S= sorts the sessions within each group by the column at point, groups keep their order, and the sort survives refreshes; ={= and =}= narrow and widen a column; === returns to urgency order.

** =drover-sidebar=

A narrow side window that stays beside your work (=drover-sidebar-side=, =drover-sidebar-width=), in a proportional font (the face =drover-sidebar=), toggled by =drover-sidebar=; =drover-sidebar-select= moves between it and your work. =n= and =p= move between sessions, =M-n= and =M-p= between groups, =TAB= folds a group. =RET= and =o= open the session in the main window, =C-o= shows it there without leaving the sidebar, and =V= shows each session there as point reaches it. The session shown in the main window is highlighted.

Every view redraws when sessions change while it is displayed; a hidden one waits until it is shown again, and costs nothing meanwhile.

* Backends

A backend registers with =drover-register-backend=, giving functions that list its sessions as =drover-session= records and act on them (open, answer, interrupt, archive, mark seen, preview, start, rename, delete, fork, compact), and reports changes with =drover-backend-changed=. See =doc/design.org=.

A front end also fits its buffers into the keys. A list of sessions sets =drover-session-at-point-function= and turns on =drover-session-keys-mode=; a prompt buffer sets =drover-session-at-point-function= to its own session and declares the prompt actions it implements with =drover-prompt-define=, such as =(drover-prompt-define 'send #'my-send)=. =drover-store-link-functions= lets a front end provide Org links to its sessions.

* Development

| Command        | Runs                                     |
|----------------+------------------------------------------|
| =make test=    | every ERT test in a batch =emacs -Q=     |

=DEPS= names the directory holding the dependencies, elpaca's builds directory by default, and =OPENCODE_EL= the opencode.el checkout the OpenCode backend is built and tested against. Tests use a fake backend, or stub opencode.el; they never touch a running Emacs or OpenCode service.
