#+TITLE: drover
#+OPTIONS: toc:nil

Drover gathers the sessions of your coding agents into one place in Emacs: which ones wait for you, which ones run, and which finished while you were elsewhere. It shows how many sessions need you in the mode line, takes you to each in turn, the one whose prompt cache expires soonest first, and lists every session, in a window, in a sidebar beside your work, or both at once, from which you can open, answer, interrupt, archive, restore, fork, compact, delete or preview any of them, as far as its front end can.

Agent front ends plug in as backends: [[https://github.com/vleonbonnet/opencode.el][opencode.el]] for [[https://opencode.ai/][OpenCode]] 2, [[https://github.com/xenodium/agent-shell][agent-shell]] for its ACP agents, and [[https://github.com/manzaltu/claude-code-ide.el][claude-code-ide]] for Claude Code in a terminal. The conversations Claude Code and Codex record are listed too, closed ones included, whichever front end ran them; opening one resumes it in yours (see [[*Closed conversations][Closed conversations]]). One prompt buffer, =*drover*=, writes to any of them: it gathers context from where you work, lets you choose the agent, model, effort and directory, and sends to a running session or starts a new one.

* Requirements

- Emacs 31.1, a Nerd Font for the status icons, [[https://github.com/magit/transient][transient]] for the menus, [[https://github.com/magit/magit][magit-section]] for the session list, and [[https://github.com/vleonbonnet/opencode.el][opencode.el]] 2.1, whose =opencode-state= session registry gives the OpenCode sessions, and whose look drover draws every session with (see [[*Look][Look]]); Emacs 31.1 is what opencode.el needs.
- Optionally, for ACP agents (Claude Code, OpenCode, Codex, Gemini CLI), agent-shell; for Claude Code in a terminal, claude-code-ide, with [[https://github.com/dakra/ghostel][ghostel]] for its statuses. Drover does not require them: their backends compile without them and load with their front end.

* Installation

With elpaca or straight, opencode.el's recipe given too, since drover requires it:

#+begin_src emacs-lisp
  (use-package opencode
    :ensure (:host github :repo "vleonbonnet/opencode.el"))
  (use-package drover
    :ensure (:host github :repo "vleonbonnet/drover")
    :hook (elpaca-after-init . drover-attention-mode)
    :bind ("C-'" . drover-dispatch))
#+end_src

The OpenCode backend loads with opencode.el, which drover does not load before you do. Its sessions come from opencode.el's registry, which follows the shared OpenCode service whether or not a session has a buffer; drover opens the service's event stream when it starts. opencode.el's hints then name drover's keys, such as "C-' A answers it" for a pending question, through =opencode-command-keys-function=, unless you set that option yourself; and =RET= on an earlier prompt quotes its line, or the region, in drover's prompt, as =C-' "= does (see [[*The prompt][The prompt]]), through =opencode-old-input-function=, likewise.

* Statuses

| Icon (Nerd Font)     | Status    | Meaning                                                 |
|----------------------+-----------+---------------------------------------------------------|
| =nf-md-help_circle=  | Needs you | A permission request or question waits for you          |
| =nf-fa-times_circle= | Failed    | A turn failed while you were not looking at the session |
| =nf-md-check_circle= | Done      | A turn ended while you were not looking at the session  |
| =nf-fa-refresh=      | Retrying  | The running turn waits to retry a failed request        |
| =nf-md-timer_sand=   | Working   | A turn runs                                             |
| =nf-fa-circle_o=     | Idle      | Nothing to do                                           |

They are opencode.el's, which its mode line and session pickers show too: =opencode-session-status-icons= changes them everywhere (see [[*Look][Look]]); the icons need a Nerd Font. In the list, the icons of Working and Retrying are animated (see [[*Animated icons][Animated icons]]).

The first three need you (=drover-attention-statuses=). Sessions are ranked by =drover-status-order=, and among those that need you the longest wait comes first; among the others, the newest turn or the latest activity, as the order of last activity places them. Whether you saw a finished turn is the backend's to know: OpenCode records it in the service, so a turn read in any client, the TUI, the desktop app or Emacs, is no longer Done.

Subagent sessions show under their parent, their icon under its title. Which of them show, =drover-show-subagents= says, and ~=u~ in the Field table of the menu (=V= in the list) cycles it:

| Mode     | Shows                                                                                          |
|----------+------------------------------------------------------------------------------------------------|
| =all=    | every subagent                                                                                 |
| =active= | the subagents in the middle of a turn: working, waiting to retry, or waiting for you (default) |
| =none=   | no subagent                                                                                    |

The list says nothing of the subagents it hides: the mode is the menu's to show (~=u~), and the list's mode line adds =+subagents= or =-subagents= while not on =active=. A subagent whose turn ended, unseen or not, is not active: it hides by default, and its parent no longer stays among the Done sessions because of it. A parent goes where the most urgent session of its visible tree belongs, so one whose subagent waits for you is listed with the sessions that need you, the subagent beneath it; a hidden subagent never places its parent in a group. A subagent matching the filter shows under its parent whatever the mode, even =none=, since it explains why its tree is listed. The mode-line count, =drover-next= and =drover-select= follow the mode too, the filter aside: they count, visit and offer the sessions the list would show without a filter, and every subagent waiting for you whatever the mode, since it blocks its parent until you answer (=drover-surfaced-sessions=).

Shown or not, a session whose subagents (at any depth) are active says so beside its status icon:

| Icon (Nerd Font)       | Means                            |
|------------------------+----------------------------------|
| =nf-md-robot_confused= | subagents wait for you           |
| =nf-md-robot=          | subagents work, or wait to retry |

The icons stay still and tell no number: their tooltip names the subagents and tells how many do each. =opencode-subagent-icons= changes the icons, which opencode.el's mode line shows too. This is how your OpenCode session shows that a subagent of its runs while it is itself idle.

* Look

Drover keeps no look of its own: the icons, faces and animations of statuses, the icons of subagents and of the archive, the faces of where a session is, of agents, of an effort chosen or inherited, of the context and the prompt cache, and how ages and token counts read are opencode.el's (=opencode-look.el=), for the sessions of every backend, so that the list, the mode line of an OpenCode session and opencode.el's pickers show a session alike; customize them there, see opencode.el's README. Drover's own are what only its list shows: its font, =drover-list= (variable pitch) and =drover-list-header=, the headings of its groups, =drover-heading=, its secondary details, =drover-dim=, the icons and names of harnesses, =drover-harnesses= and =drover-harness-default-icon= in the face =drover-harness= (see [[*Harnesses][Harnesses]]), and the mode-line count's glyph, =drover-attention-glyph=.

* Attention

=drover-attention-mode= shows how many sessions need you in the mode line, as other indicators show a count: a robot (=drover-attention-glyph=, the emoji 🤖), a space and the count, such as =🤖 3=, in the face of the most urgent status among them, and nothing when no session needs you. It counts the sessions the list shows under its subagent mode, and the subagents waiting for you whatever the mode (see [[*Statuses][Statuses]]). With a Nerd Font, a Nerd icon may suit your mode line better, such as ="\U000F16A4"= (=nf-md-robot_excited_outline=): an icon drawn wider than its room, as the Nerd Fonts but their Mono variants draw icons, is kept off the count, measured once per font. The count begins with the robot: what parts it from the indicator before it is your mode line's. Its tooltip lists the sessions in the order =drover-next= visits them, with the time left of each live prompt cache, such as =cache 4m=; clicking it runs =drover-next=, the right button =drover-select=.

- =drover-next= visits the sessions counted, in turn. First come those whose prompt cache is live, the one to expire soonest first, so that you answer them while their next turn still costs less; a cache is live as the list shows it (see [[*Prompt caches][Prompt caches]]), so an expired one counts as none, and so does a subagent's. A subagent waiting for you is visited through the top of its tree, whose buffer answers it (=A=) and whose turn your answer resumes: it ranks by that session's cache, and the tree comes once, however many of its sessions need you. Then come the others, in the order the list and the sidebar show them, which share the view settings: as you group and sort them (~=g~, ~=o~, ~=r~), group after group, each subagent under its parent. A subagent waiting for you that the list hides comes where the list would show it, and a session the filter leaves out after those it keeps, in the order the list would show it without the filter. The first press lines them up in that order and visits the first, even the session you are on; each press after it visits the next of that queue, the first again after the last, as long as you press nothing else in between, as =undo= chains: the key of its own, the mode line, or the menu (=j=), opened and closed as many times as you like. Any other command ends the round, and the next press lines the sessions up anew, as they then stand. Until then nothing that happens to sessions changes the queue, a session coming to need you, one you answered or a cache renewed or expiring; a session gone is passed over, and one that fails to open is told on one line, the next press going on past it. From the sidebar, sessions show in the window beside it, and from the prompt's side window in the window you came from. The echo area tells only its place in the round, such as =2/5=, since the buffer visited shows the session; =drover-attention-echo= set to nil silences it.
- =drover-select= picks any session the list shows under its subagent mode, and any subagent waiting for you, with completion, those needing you first, in the order =drover-next= visits them, then the others, most urgent first, grouped by status and annotated with its project, branch, age and what it waits for. With a prefix argument it opens the session in another window.
- =drover-mark-all-seen= marks every Done and Failed session seen after confirming how many (=drover-catch-up-statuses=); with a numeric prefix argument, only those that ended at least that many hours ago. Useful to start from a clean slate, or after a day away.
- =drover-bury-quiet-sessions=, =B= in the menu, puts away the buffers of the sessions that do not need you, idle, working or retrying, leaving at hand those that do (see [[*Global keys][Global keys]]).

* Keys

Drover binds no global key. Its commands are gathered in one menu, =drover-dispatch=; bind it to a key you can reach from anywhere, for instance:

#+begin_src emacs-lisp
  (keymap-global-set "C-'" #'drover-dispatch)
#+end_src

or, with =use-package=, =:bind ("C-'" . drover-dispatch)=. The keys come in four sets, and no key belongs to two, so the menu holds them all: the global keys everywhere, the session keys in lists of sessions and in prompt buffers, the prompt keys in prompt buffers, the view keys wherever one of drover's lists is in sight. What may apply but does not now is greyed out rather than hidden, and a group none of whose entries applies has its title greyed out too; what cannot apply where you are is left out: the view keys while none of drover's lists is in sight, and the prompt keys that edit or read a prompt buffer (=S-RET=, =i=, =k=, =/=, =@=, =y=, =t=, =T=, =O=) outside prompt buffers. You may bind the menu to several keys: whichever opened it closes it. =q= closes it too, as =C-g= does, and every other menu of drover's (=V= in the list, the search's, the usage report's, the prompt's choices). The echo area and the hints, such as =C-' X stops=, name the key Emacs's help names for the menu; set =drover-dispatch-key= to name it otherwise, such as ="Caps Lock"= when a key remapper sends that key to Emacs as =<f19>=.

** Values and layout

Settings show their value beside the key that changes it, as Magit's menus show theirs: what the prompt or the session runs, the sort, the grouping, each filter, the subagents, older and archived sessions shown, follow mode and the columns. A value chosen is highlighted, one inherited from the defaults dimmed; changing a setting leaves the menu open, its value redrawn.

The menu has no fixed shape: its groups fill columns of balanced height as wide as its window, one after the other as text fills a newspaper's columns, and in rows of such columns when the window is narrow, so that it takes as few lines as the width allows: across 240 columns, nine to twelve; across 160, fifteen to seventeen; across 100, about twenty-five, in rows. A group may show in two or three columns side by side, or in one, as the room asks. While the menu stays open, its groups keep their place as long as they fit, as values change or you move in the list. In drover's prompt, the list in sight, 160 columns wide, it reads:

** Session keys

In every list of sessions (drover's list, and the lists of other front ends that turn on =drover-session-keys-mode=) these keys act on the session at point directly; in a prompt buffer, such as an OpenCode session buffer, they act on its session through the menu.

=A= answers in place, from where you are. A session with no request of its own answers the request of its subagent, at any depth, waiting the longest, whether its parent runs it in the foreground or in the background, so you need not go to the subagent first; its own request comes first. It applies when a session of the tree waits for an answer.

| Key | Command                    | Action                                                         |
|-----+----------------------------+----------------------------------------------------------------|
| =o= | =drover-open-other-window= | open it in another window than =RET= would                     |
| =A= | =drover-respond=           | answer its question or permission request, else its subagents' |
| =<tab>= | =drover-build-and-go= | switch to its engine's build agent (OpenCode's =build=, Claude Code's mode for =build=) and send "Go ahead" |
| =E= | =drover-edit-pending-prompt= | withdraw a prompt it has not taken yet, to edit it          |
| =K= | =drover-interrupt=         | interrupt its turn, after confirmation                         |
| =s= | =drover-mark-seen=         | mark its ended turn seen                                       |
| =u= | =drover-open-parent=       | open its parent session                                        |
| =c= | =drover-open-subagent=     | pick one of its subagent sessions and open it                  |
| =r= | =drover-rename=            | rename it                                                      |
| =x= | =drover-delete=            | delete it for good, after confirmation                         |
| =z= | =drover-archive-toggle=    | archive it, and close its buffer; restore it when archived     |
| =Z= | =drover-wrap-up=           | have it clean up after itself, then archive and close it       |
| =g= | =drover-refresh=           | refresh the list, or reload the session's buffer               |
| =+= | =drover-new-session=       | start a session in its directory                               |
| =v= | =drover-peek=              | preview where it stands, without opening (lists)               |
| =R= | =drover-review=            | review the changes it made, and comment on them                |
| =G= | =drover-goal=              | set a goal on it, or pause, resume or stop the one it has      |
| =V= | =drover-view=              | the View menu: the view keys alone (drover's list)             |

=<tab>=, the physical Tab key in graphical Emacs, switches an OpenCode session to the =build= agent and sends exactly "Go ahead", after the switch settles, leaving any draft intact. It works in the lists and through the dispatch menu. =TAB= (=C-i=) still expands or collapses sections; a terminal must report Tab separately from =C-i= to distinguish these bindings.

=RET= opens the session at point, and =1= to =9= the sessions of those numbers, =0= the last, counting the sessions at the top of their trees as the list shows them, but subagents and the sessions of collapsed groups (see [[*The List group][The List group]]). The usual keys of each list stay: =n= and =p= move, =TAB= folds (but in the sidebar, which folds nothing), =q= quits; Magit's =1= to =4=, which show sections down to a level, give way to the digits. =RET= opens it where the list sends sessions: from a side window, in the window where you work; from an ordinary window, in the list's own window. =o= opens it in another window than that one: the window already showing the session, else the one used last, else a window split from it; never in a side window, a window dedicated to its buffer or either list. Drover chooses the window and selects it before the backend shows the session, so sessions of every backend open alike. In lists drover does not draw, =drover-session-keys-mode= adds these keys. opencode.el lists no sessions of its own: drover's list shows them.

=E= takes back a prompt sent to the session that it has not taken yet, such as one sent while a turn runs, which waits pending for the next step or the turn's end: the front end withdraws it, and its text goes into =*drover*=, set to go to that session (see [[*The prompt][The prompt]]), its attachments with it, to be edited and sent again. With several pending, which one is read. The menu shows how many are pending beside it, and greys it out when none is; for OpenCode, the session's buffer keeps its pending prompts, shown or not, and a session without a buffer has none to take back. A pending prompt withdrawn from the session's buffer, by a click, goes into =*drover*= too (=opencode-withdrawn-prompt-function=, which drover sets to =drover-opencode-edit-withdrawn= unless you set it yourself; set it to =opencode-put-old-input= to edit it in the session's input).

=r= renames a session in its front end: an OpenCode session on the service, an agent-shell shell's buffer and its viewport, a claude-code-ide session through Claude Code itself, =/rename TITLE= typed in its terminal once its turn ended and its input box is empty, so that Claude Code's desktop app and its =/resume= picker show the new title too. Until you rename it, a shell of agent-shell is named after the title the list shows as the title changes: the agent's, or until the agent gives one the first prompt, cut to =drover-agent-shell-name-limit= (60) characters, rather than =Claude Agent @ PROJECT=. A buffer you renamed yourself keeps its name, and =drover-agent-shell-name-after-title= set to nil leaves shells named as agent-shell names them. A claude-code-ide terminal likewise is named after its conversation's title, as =drover-claude-code-ide-rename-format= says, =*claude* TITLE=, cut to =drover-claude-code-ide-name-limit= (60) characters, rather than after the terminal's title, which Claude Code sets to the kebab-case name it gives a session as you approve its plan; =drover-claude-code-ide-name-after-title= set to nil leaves terminals named as claude-code-ide and the terminal's title name them.

=z= archives a session in its front end's archive, such as OpenCode's, or in drover's own when its front end has none, without asking, and closes its buffer (see [[*Archived sessions][Archived sessions]]); on an archived session, from the list showing archived sessions or from the session's buffer while it is open, =z= restores it. The menu names what it does, =Archive= or =Unarchive=. =Z= wraps a session up: its agent is told you are closing it and cleans up what it left behind, then it is archived and its buffer closed, unless the agent asks you something first (see [[*Wrapping sessions up][Wrapping sessions up]]).

=s=, =K=, =z=, =Z= and =x= act on every session selected, when a region selects several (see [[*Selecting sessions][Selecting sessions]]): =K= on those that run a turn, =s= on those whose turn ended unseen, =z= on those not archived, or restores them all when all are, =Z= on those that may be wrapped up; =K= and =x= after one confirmation naming them all, such as =Delete 3 sessions for good: A, B, C?=, and each with one report, such as =Archived 3 sessions=, naming those that failed without stopping the others; a confirmation names five of them at most, and counts the others.

Acting on hundreds or thousands of sessions at once, such as archiving every session a list shows, never stops Emacs: drover acts on them a few milliseconds at a time, between which Emacs redraws and reads your keys, with at most =drover-bulk-requests= (8) requests awaiting the service's answers, the next sent as answers come. The OpenCode service answers archives, restores, interrupts, marks seen and deletions alike. The echo area tells how far it is, such as =Archiving 340/2202 sessions…  C-' X stops=, =drover-stop-actions= (=X= in the menu, shown while an action runs, its progress beside it) stops it, leaving the sessions not reached as they were, and one line reports it at the end, such as =Archived 2199 sessions; 3 failed: A (…), B (…), C (…)=, as a warning when some failed. A session the service never answers about fails after =drover-bulk-timeout= seconds (120). The list follows as usual, drawing once the answers settle; acting again on sessions an action still acts on does nothing more.

To store an Org link to the session at point, use Org's own =org-store-link= (=C-c l=) with a link type of your own whose store function reads =drover-session-at-point=. Drover makes its links the same way (=drover-session-link=): =M-w= in the list copies them, and the prompt quotes them.

** The menu beside the list

The session keys of the menu act on the session the current buffer tells: the one at point in a list, the buffer's own in a session buffer. In a buffer telling no session, such as the prompt, =*drover*=, or a file you edit, while one of drover's lists, the sidebar or the other, shows in a window of the frame (the one used last, if both do), they act on that list instead: on the session at point of the list's window, as if typed there, and so does =v=. A session buffer keeps acting on its own session; =v=, which peeks at a list's session, needs the list. The global and prompt keys keep to the current buffer.

The view keys apply wherever one of drover's lists is in sight, in a window of any visible frame, a session buffer included, since what they change is shared by both lists: sort, group, filter, columns, subagents, older and archived sessions. =-f=, follow mode, is the list's own: it sets that of the list the menu acts on, else of the list shown on the frame. With no list in sight, they are greyed out.

The List group, whether the menu opened in the list or beside it, moves the point of the list's window, the menu staying open and following the new session at point: its title names it, and what applies to it is greyed out anew. Follow mode shows each session as you go, its title taking the colour of the session you work in, as moving in the list would.

*** The List group

While the menu acts on drover's list, here or beside, it shows a group more, named after the session at point; there =RET= opens that session rather than send, so the Input group shows Send on =M-RET= instead, which sends drover's prompt when it holds one:

#+begin_example
  List: Fix the login redirect …
   C-n Next session
   C-p Previous session
   M-n Next group
   M-p Previous group
   M-< First session
   M-> Last session
   1…9 0 Open by number
   RET Open
#+end_example

| Key       | Command                        | Action                                          |
|-----------+--------------------------------+-------------------------------------------------|
| =C-n=     | =drover-list-next-session=     | the next session, over group headings           |
| =C-p=     | =drover-list-previous-session= | the previous session                            |
| =M-n=     | =drover-list-next-group=       | the first session of the next group             |
| =M-p=     | =drover-list-previous-group=   | the first session of the previous group         |
| =M-<=     | =drover-list-first-session=    | the first session                               |
| =M->=     | =drover-list-last-session=     | the last session in sight                       |
| =1=…=9=   | =drover-list-open-numbered=    | open the session of that number, as =RET= would |
| =0=       | =drover-list-open-numbered=    | open the last session in sight                  |
| =RET=     | =drover-open-at-point=         | open the session at point, as =RET= in the list |

Sessions of collapsed groups are passed over. The digits count the sessions at the top of their trees, in the order the list shows them: subagents are not numbered, so that a number stays with its session as subagents come and go. Opened by number, a session opens as =RET= at its row would, the list's point moving to it: =C-' 3=, in a file beside the sidebar, opens the sidebar's third session in the window where you work. The digits work wherever one of drover's lists shows on the frame, a session's buffer included: there the menu acts on the buffer's session, and the List group shows only =1…9 0 Open by number=, for the list in sight. =RET= opens the session as =RET= in the list would: from a side window, in the window where you work; from an ordinary window, in that window, or with =C-u=, the menu's prefix argument, in another one. In a buffer sending prompts, such as =*drover*=, =RET= stays Send: a prompt lost to a slip of the finger costs more than reaching for =o=, which opens the list's session in another window. So does it from any other buffer, a file you edit beside the sidebar, while =*drover*= holds a prompt to send, more than blanks: =C-' RET= sends it, hidden or not. Only in the list itself does =RET= open the session while a prompt waits, as =RET= does there; =C-' M-RET= sends the prompt from the list. The menu never shows the two =RET=. The moving keys bind nothing in the list itself, where Magit's =n=, =p=, =M-n= and =M-p= move; the digits do, in both lists.

* The list

=drover-list= shows every session in a Magit-style buffer, =*drover sessions*=, in an ordinary window: the one already showing it, else the selected window, which it takes rather than splitting, or, from a window that may not show it, such as the sidebar's or one dedicated to its buffer, the window where you work, as sessions opened there do; =q= brings back the buffer it replaced. With a prefix argument it shows in another window, as =o= opens a session in another window (=drover-list-display-action=, =drover-list-other-window-display-action=). =drover-list-side= shows the sidebar, a list of its own, =*drover sidebar*=, in a side window beside your work (=drover-list-side-window-side=, =drover-list-side-window-width=), or hides it, and with a prefix argument moves between it and your work. Both may show at once, each laid out for its own width, typically two lines per session in the sidebar and columns in the other; each has its own point and its own follow mode, and the keys act in the list you type them in. What they list, how they sort, group and filter, and which subagents and archived sessions show are the same for both: the View menu changes them for both. In =*drover sessions*=, groups and sessions are sections: =TAB= folds a group, or recaps the last turn of a session (see [[*The last turn][The last turn]]). Grouped by status, the Idle group starts collapsed (=drover-list-collapsed-groups=); what you collapse or expand survives refreshes. Each list draws the sessions of its first screens at once, and the others a few at a time while Emacs is idle (=drover-list-deferred-delay=), or at once as you search it, copy it, scroll near them or move to its last session: thousands of sessions show in tens of milliseconds.

The sidebar folds nothing (=drover-list-sidebar-mode=): a session shows its line, or two, and no recap, a group every session it holds, and =TAB=, Magit's other folding keys and clicks on a heading do nothing there; expand a session in =*drover sessions*=, or peek at it with =v=. It draws the sessions of its first screens at once, and the others later, as the list does. So its lines begin with their icons, at the window's left edge, and its side window has no fringes, left nor right: drover sets them on that window alone, as it shows the sidebar and whenever it draws it there, so that a side window that had some, such as one shown before you updated drover, loses them, so that your other windows keep theirs, and a window showing the sidebar's buffer otherwise, or the side window another buffer, has the fringes of its buffer, as any window. Without a right fringe, Emacs keeps the last column of a window for the =$= telling that a line is cut, as wide as =$= in the list's face, wider than its average character in most proportional fonts: lines leave that room, so that none is cut.

The sidebar shows no cursor: the row at point stands out, a little more than Magit's highlight of the current section (=drover-list-sidebar-highlight-contrast=, its background as far again from the default one, as the theme draws them, drawn anew when you change themes; the face =drover-list-sidebar-highlight= sets it otherwise), and point stays at the start of a row, a session's or a group's heading. =C-n=, =C-p= and the arrows move by rows, over a session's second line, the mark with them (=drover-list-next-row=); a scroll or a search ended takes point to the start of its row. A click on a session's row opens it, as =RET= there does, once however many times you click; one on a group's heading does nothing, and the mouse drags no region. A region still selects the rows from its start to its end. =*drover sessions*= keeps its cursor and moves by lines.

The sidebar next to =*drover sessions*= would show the same sessions twice, side by side: while a window shows the list beside it, the sidebar steps aside, and comes back where it was, on its side, in its slot and as wide as you left it, once no window shows the list there: the list's window shows another buffer, is quit, deleted or moved, or the list is buried. A list elsewhere on the frame, such as in the right half of a window split, or on another frame, leaves the sidebar where it is. =C-' L= while the list is beside it shows the sidebar all the same, and it stays until the list leaves; hiding it then, with =C-' L= or =q=, means it does not come back. A buffer you choose through the minibuffer, as with =consult-buffer=, which shows each candidate in your window as you move to it, is followed once you chose: Emacs puts the windows back as they were when the minibuffer exits, so the sidebar steps aside from the list, or comes back, only then.

By default the list is not grouped, and sorted by last activity, newest first (see [[*The order of last activity][The order of last activity]]): the sessions running a turn come first, the turn started last on top, then the others, the one active last first, whether it needs you or not. The View menu groups and sorts otherwise; set =drover-group-by=, =drover-sort-by= and =drover-sort-descending= to keep another view, such as =status= and =urgency=, not descending, the view of earlier versions.

The buffer shows sessions, and how many each group holds, nothing else: no line counts them at the top, as the mode line counts the sessions that need you (see [[*Attention][Attention]]); which subagents show, the filter, the sort and the keys are the menu's to show (=C-'=, or =V= in the list), and the mode line's to hint at, such as =ungrouped, last activity ↓ filtered=. A filter leaving every session out says =No session matches the filter.=, and a list without sessions =No sessions.=; the View menu tells which filter, and clears it.

From the sidebar, =RET= opens the session at point in the window where you work, never in the other list, =o= in another window than that one, split from it when there is none, =C-o= shows it where =RET= would and leaves you in the sidebar, and follow mode shows each session there as point reaches it. In either list, the colour of a title tells where its session is (see [[*Where sessions are][Where sessions are]]).

** What a line shows

The list is drawn in a proportional font (the face =drover-list=), laid out in pixels, and what a line shows depends on the width of its window. =drover-list-fields= ranks the fields a line may show and the room each needs:

| Field    | Column   | Shows                                                                       | Rank | In two lines          |
|----------+----------+-----------------------------------------------------------------------------+------+-----------------------|
| title    | Session  | the status icon, the icon of active subagents and the title, always         |    0 | first line            |
| age      | Age      | how long it has been active, or needed you                                  |    1 | first line, right     |
| cache    | Cache    | the prompt cache's lifetime left: a short bar and the time left             |    2 | the line's background |
| summary  | Summary  | what it waits for, or where it stands, as a model summarized it             |    3 | second line           |
| harness  |          | what runs it, its icon, its name in the icon's tooltip (see [[*Harnesses][Harnesses]])     |    4 | first line, its icon  |
| model    | Model    | the model, compact, such as =Opus 5.5=, then its effort, dim when a default |    5 |                       |
| context  | Context  | the context's size, such as =182k=, after a short bar of how full it is     |    6 | first line, a pie     |
| changes  | Changes  | what all its turns changed, such as =+42 −7 · 3f= (see [[*What sessions changed][What sessions changed]]) |    7 |                       |
| provider | Provider | the provider serving the model, as an icon                                  |    7 |                       |
| location | Project  | the project                                                                 |    8 |                       |
| branch   | Branch   | the Git branch, greyed out when the repository's default one                |    9 |                       |
| agent    | Agent    | the agent, as =@build=, in its colour                                       |   10 |                       |
| created  | Created  | how long ago it was created                                                 |   11 |                       |

The list shows the fields with something to show, by rank, as long as they fit, as aligned columns, but those you hide (=drover-list-hidden-fields=, or the menu's Columns). What a turn changes changes no field shown: the summary keeps its column while no session needs you, lending its room to the others until one does, the prompt cache while no cache is live, for the sessions of a backend that reports caches (OpenCode's, when the service lists them), and the room a title needs counts from the icon of a session alone, not from the subagents at work under it. So sending a prompt, a session going to work, answering, starting subagents, never makes a column appear or leave. A wider window adds model and effort, context, provider, project, branch, agent and creation time as they fit beside the title, host, harness, age, cache and summary. When not even the summary and the harness's icon fit beside the title, host, age and cache, each session takes two lines instead: its icons, title and age, then, each in a cell as wide as the widest icon of its kind, so that the icons line up whatever the ages, a pie of how much of its context it fills, by eighths (=drover-context-pie-icons=, its tooltip telling the size and the model's), a network icon after another host's name (=drover-host-icon=, nf-md-server_network, dimmed while connected, in =drover-host-disconnected= while not; its tooltip names the host and tells whether it is connected, such as =reaver — disconnected for 5m=), and the icon of its harness, last; and under them, for a session that needs you, what it waits for. This host's name uses the theme's success colour (=drover-host-local=), without a host icon. A cell is kept while a session listed shows something in it, those without leaving it empty: the host's while a session of another host is listed unless grouped by host, the pie's while a session's context size is known. The model and provider then show in its details, =TAB=, and its tooltip, and the harness's name in its details and its icon's tooltip; the context, which the columns need not show for the list to use them, as the pie alone. The sidebar, to keep its lines compact, shows another host by its icon alone, in two lines and in columns, where its column, as wide as the icon and nameless, comes before the harness's, after the age's and the cache's: the host's name and since when it is not connected are in the icon's tooltip, the face of the icon telling at a glance whether it is connected. Local sessions show no host in the sidebar, and a sidebar of only local sessions reserves no host column or icon cell; the list in an ordinary window keeps the host's name and age, in two lines as in its column. The layout is computed again whenever the window's width changes. One space parts each icon from the next and from the title, and columns stay aligned to the pixel whatever the icons before them.

In columns, the header line names each column (the =:label= of its field), aligned to it to the pixel, past line numbers if you show them; hover a name to read what its column shows. A column is at least as wide as its name, room allowing. Two lines have no header line.

A column is as wide as what it shows, up to its field's =:max=. On a line too narrow for every column, the summary gives up room first, then the names of the columns of short texts, then the title, then the project, branch, agent and model, in proportion; the ages, context, cache, changes, cost and provider are never cut, nor the model's effort, which keeps its place while the model's name is cut, such as =Opus… high=. The harness's column shows its icon alone, as wide as the icon and unnamed in the header line, the harness's name in the icon's tooltip and the session's details. A column gives up only the room missing: no column is narrowed while the line has room.

The branch of a session working on its repository's default one shows greyed out, in =opencode-setting-inherited=, as a model's default effort does, so that a feature branch stands out and an empty cell means no branch: the default is the one the repository's remote names (=refs/remotes/origin/HEAD=, read from the file system, as is every branch, without running Git), else =main= or =master= (=drover-default-branches=). Its column is ten characters wide at most, so that a long branch takes no room from the other columns: a longer branch is cut, such as =feature/a…=, and told whole in its session's details, as a branch its line leaves out is. Grouped by branch, the group names it instead.

The agent is drawn as =@build=, bold, the =@= in its face too, so that it reads as one word, as an agent mentioned in a prompt is spelt. OpenCode sessions show their agent as opencode.el's mode line does (=opencode-agent-display=): the catalog's name, in the agent's configured colour, else in a face of =opencode-agent-faces= by its place among the primary agents; plain until the catalog arrives. Other backends' agents take a face of =opencode-agent-faces= by their name.

The model's effort is green when chosen (=opencode-setting-chosen=) and dim when it is the model's default (=opencode-setting-inherited=), as in the prompt's header and opencode.el's mode line; its tooltip says which. An agent-shell shell left on its agent's own =default= level, as Claude Code's agent offers, shows the level its model takes by default, dim, as Claude Code's catalog or what drover learnt of the model tells it, and no effort when neither does. The provider's icon comes from the backend, such as opencode.el's =opencode-provider-icons=, its tooltip naming it. The context's bar fills as the context nears the model's size; near a long-context price tier, past which requests cost more, its size turns to =opencode-context-near=, past it to =opencode-context-over=, and the bar's filled part takes that colour, the rest of the bar =opencode-context-bar=; the tooltip tells the tokens, the model's limit and the tier. A size the service only estimated, as OpenCode does after compacting a conversation until its next step measures it, begins with =~=, such as =~41k=, and its tooltip says so. The context costs a request per session to some backends, OpenCode's among them: the list asks for it only for the sessions in sight, those of expanded groups, while columns or the pie of two lines may show it.

Each icon takes the room its font draws it in, which may be wider than the room the font gives it: the Nerd Fonts but their Mono variants draw icons up to half a cell past their advance, and drover measures that ink in the fonts of the list's window, so no text is drawn on an icon. Every status icon takes the room of the widest, so titles line up whatever the status. A subagent's icon stands under its parent's title, past the icons of the parent's active subagents.

** Where sessions are

The colour of a session's title tells where the session is in Emacs:

| Face                      | Inherits                       | The session                                                                                            |
|---------------------------+--------------------------------+--------------------------------------------------------------------------------------------------------|
| none                      |                                | has no buffer                                                                                          |
| =opencode-session-open=   | =font-lock-keyword-face=       | has a buffer no window of a visible frame shows                                                        |
| =opencode-session-shown=  | =font-lock-type-face=          | shows in a window of a visible frame                                                                   |
| =opencode-session-active= | =font-lock-function-name-face= | shows in the window you work in: the selected one, or the one selected before a list or the minibuffer |

The three faces inherit sibling faces of font lock, which themes tell apart from one another and from the default foreground; none of them is a status's, so a title never reads as a status: the faces of =success=, =warning= and =error= colour the Done, Needs you and Failed icons. =font-lock-function-name-face= names where you are elsewhere too: =which-function-mode= shows the function point is in with it. Over an idle session's dimming, they lend the dimming what they do not set.

As you select windows and show buffers in them, only the titles whose session changed place take their new face, in place; the list is not drawn anew, but when a face would change the width of a title, as a bold one would. A buffer opening or closing is a change its backend reports, which redraws the list. opencode.el's session pickers title sessions in the same faces. =drover-list-current=, the face of the former highlight of the session beside the list, is an obsolete alias of =opencode-session-active=.

** The last turn

Expanded, a session recaps its last turn under its title, in the list's font, then the files all its turns changed:

         #+begin_example
         ✓  Fix the login redirect          plan  Opus 5.5 high  +42 −7 · 3f   1h
            Prompt   The login page sends users back to /home after they sign
                     in; keep the page they came from.
            Reply    The redirect now keeps the page users came from, in a
                     signed parameter, …
            Changes  auth/login.go  +30 −5
                     auth/redirect.go  +10 −2
                     auth/redirect_test.go  +2
         #+end_example

         - its title, when its line cuts it;
         - what the session waits for, every question or permission request in full, and the error that ended its turn or that it retries after, but an error its line shows whole already; when its line leaves out its summary, how it stands, such as the step it is at;
         - the prompt it was given last, and the agent's newest reply since, a few lines each, wrapped to the window (=drover-list-recap-lines=): =v= previews the whole reply, =RET= opens the session;
         - the files all its turns changed, a line each, with the lines added and removed when the engine counts them, after their counts when its line does not show them (see [[*What sessions changed][What sessions changed]]); without them, the files its last turn changed, as its backend tells them;
         - what the session's line leaves out at this width, or shows cut or as an icon alone, such as the model, provider and context in a side window, the harness's name where its column shows its icon, the context's size where its pie shows, and the directory of a session without a project; not what the group it is in names, such as its project.

         A session whose line shows everything it would tell has no details to expand.

The recap is fetched as the session expands, without waiting: =loading…= shows meanwhile. It is kept until the session changes, fetched again then at most every two seconds while the session stays expanded, and anew by =g=. OpenCode sessions ask the service (=opencode-session-last-turn=), Claude Code conversations, in a terminal or closed, read their transcript, closed Codex ones their rollout, and agent-shell's shells tell what their events said since drover followed them.

** What sessions changed

The column =changes= tells what a session changed in all its turns, as its engine recorded them: the lines added and removed, and the files, compact, such as =+42 −7 · 3f= or =+45k −6.1k · 409f=, past a thousand lines in thousands and the files as a count and an f, which the details tell whole, the counts in =drover-added= and =drover-removed=; its expanded session lists the files (see [[*The last turn][The last turn]]). They are what a review of the whole session shows (see [[*Reviewing a session's changes][Reviewing a session's changes]]): OpenCode's service diffs the snapshots it took of the working tree, Claude Code's and Codex's edits are read from their transcripts and rollouts; no model is asked. An engine telling none, such as Gemini CLI's, shows none.

Reading them costs a request to the service or a whole transcript read, so drover reads them only for the sessions a list shows, those of its expanded groups and those you expand, once their turns end, never while they work: =drover-changes-delay= seconds after a session settled, two at once at most (=drover-changes-concurrency=), the most recently active first. What it read it keeps in =drover-state-directory=, =changes.eld=, the newest 1000 conversations, each with the time of its session's last activity it describes, so that an Emacs starting reads again only the sessions that changed since. A session that could not be read is read again once it changes. Another host's sessions carry what their owner read, which it reads for the sessions your lists show.

** Summaries

With =drover-summary-mode= on, such as by =(add-hook 'drover-start-hook #'drover-summary-mode)= in your configuration, which turns it on as drover starts, a cheap model writes, once a session's turn ends or it waits for you, one line on where it stands, five words at most, short enough for the sidebar to show whole, a longer one keeping the clauses that fit, such as =Waiting: approval to push= or =Done: FTS search, tests pass=, a recap of the turn in two to four lines, and a few sentences on the whole session for the session's buffer, which recall what it is about: its subject first, as its first prompt set it, then how it went, then where it stands and what comes next. The line is the session's summary: its column, the second line of the sidebar, its tooltip, the mode line's tooltip and the annotations of the search show it; the recap comes first in its details, above the last turn as it was said (=summary= in =drover-list-recap-lines=). Until it is written, while the session works, or when it cannot be, they show what they showed before: the request a session waits for, or its error.

A summary is asked for =drover-summary-delay= seconds after a session settled, never while it works, two at once at most (=drover-summary-concurrency=), and from the recap of its last turn its backend tells: your last prompt, the agent's final reply, the files changed, the error and the requests waiting, at most =drover-summary-input-limit= characters; with it the session's title, its first prompt (OpenCode's service tells it, Claude Code's and Codex's records too) and what the model wrote of the session after the turn before, a quarter of that each, obvious secrets redacted (private keys, tokens of known services, credentials in headers and URLs, values assigned to names such as =password=, long strings mixing case and digits, and =drover-summary-redactions=). A turn summarized once is not summarized again: summaries are kept by conversation in =drover-state-directory=, keyed by the text the model read of the turn and the first prompt, so that neither a rename nor what was written of the session asks again. Sessions found settled as Emacs starts are summarized only when active in the last =drover-summary-catch-up= seconds; =M-x drover-summarize= summarizes the session at point now, anew with a prefix argument.

The model is this host's cheap model, or the next of its chain when one is unavailable (see [[*The cheap model of a host][The cheap model of a host]]), at variant =low= when it offers it (=drover-summary-variant=), or the model =drover-summary-model= names, as =PROVIDER/MODEL=, through OpenCode's service: a stateless generation (=POST /api/experimental/generate/text=) that makes no session, so that none shows among your sessions nor counts in their usage, and needs no credentials but the provider's the service has. Where no cheap model resolves, only the turns needing no model are summarized, which is said once, until the catalogs offer one. Summaries need the service running, and never start it; once one failed, none is asked for =drover-summary-rest= seconds but those you ask for, and the failure is said once. At most =drover-summary-daily-limit= summaries are written a day (1000); =drover-summary-usage= tells how many were, and the characters read and written. =drover-summary-harnesses= chooses the backends summarized: the text of the others' turns is never sent; another host's sessions show the summaries their host wrote.

The buffers of sessions show what was written of the whole session, as Claude Code shows its recap above its prompt: dimmed, just above their input, while the session is idle, so that the last turn, right above, reads in its context; else, for a turn summarized before, the line and its recap. opencode.el's buffers, this host's and those of another host's sessions, whose owner wrote it, show it as read-only text that point moves through and =RET= quotes, and agent-shell's above their prompt.  Claude Code's terminal shows its own recap.  =drover-brief-in-buffers= turns it off; opencode.el's look is =opencode-session-summary-icon= and its =opencode-session-summary= faces.

** The cheap model of a host

Small requests, such as summaries, run the cheap model of the host they run on, which =drover-model-cheap= tells: =M-x drover-model-cheap= names it and the models tried after it, or says why there is none, and =drover-model-cheap-fetch= hands it to a function, for other uses. It is chosen from the catalogs of the host's OpenCode service, the models of its providers with their families, release dates and costs, and how the service is signed in to each provider, which its integrations tell: a login, such as ChatGPT's, Claude's or Copilot's, is a subscription, a key an API; a provider of no integration, which a plugin or the configuration defines, uses its own credentials; one whose integration is not connected is never used. It is chosen again as those change.

Every cheap model a usable provider offers is ranked: a model of a tier of =drover-cheap-families=, Haiku, then Luna, then the flash models of DeepSeek and GLM. Models are current or outdated first: each family's current version is the newest the host's usable providers offer, read from the models' identifiers (=drover-cheap-versions=: =claude-haiku-5-5= and =claude-haiku-5.5= are Haiku 5.5, =deepseek-v4p1-flash-1017= DeepSeek V4.1), never from release dates, which providers tell differently, or not at all; an older version, or a model whose identifier tells none when another tells one, such as a router to the latest, is outdated, and comes after every current model, never dropped. Then providers come in the order of the classes of =drover-cheap-provider-orders= for the kind of the host, =drover-cheap-host-kind=, which each host's configuration sets, never guessed: a =mongodb= host uses MongoDB's AI providers alone, Copilot, then the Grove gateway's (=ai-gateway-*=), Fireworks, then the ProdSec gateway; a =personal= host prefers subscriptions, then MongoDB's providers as the MongoDB relay serves them, then APIs. A provider belongs to the first class of that order it is of (=drover-cheap-provider-classes=: an identifier, or how the service is signed in to it); =drover-cheap-excluded-providers=, by default Secateur's copies of the Grove gateway, are never chosen. Then the tier, then the newer version and the model released last, a model listed without a date taking the date the catalog gives its name elsewhere; of models released the same day, a premium edition, such as =gpt-6-luna-fast=, comes after (=drover-cheap-premium-regexp=), then the cheaper. Disabled and deprecated models are never chosen, nor those of =drover-cheap-excluded-models=, by default spot capacity, which the provider may take back. =drover-cheap-rank= ranks them all.

The model is the first, and the chain the best model of each provider, in that order (=drover-cheap-chain=): what makes a model unavailable, a quota, a login, an outage, is mostly its provider's. On a MongoDB host signed in to Copilot, such as Reaver, that is Copilot's Haiku 5.5, then the Grove gateway's Luna 6 and DeepSeek V4.1, then Fireworks' DeepSeek V4.1, never its spot capacity, then the ProdSec gateway's Haiku 5.5, the gateway's Haiku 4.5, outdated, last; on a personal one signed in to ChatGPT, such as Core, ChatGPT's Luna 6, before the Haiku 5.5 the relay serves, since the provider comes first, then the tier, then the relay's Luna and DeepSeek, then OpenCode's free DeepSeek.

=drover-cheap-generate= has the cheap model write what a prompt asks, through OpenCode's stateless generation, the instructions it is given folded before the prompt, since the route takes a prompt alone, at =drover-cheap-variant= (=low=) when the model offers it, waiting =drover-cheap-request-timeout= seconds. A model unavailable, out of quota or not signed in, a provider failing or not answering in time, leave the next of the chain to answer, =drover-cheap-attempts= models at most (4); content a provider refused or a request found invalid would fail with any model, and is told at once. It calls its function once, with the text and the model that wrote it, or why none did, and returns a function cancelling the request.

=drover-cheap-title-mode= has OpenCode title its sessions with the cheap model too, rather than the small model it picks from the session's provider, or the free one Copilot offers for titles. It names the cheap model, at =drover-cheap-variant=, for OpenCode's title agent in a configuration file of the service's own, =opencode.json= in its global configuration directory (=drover-cheap-title-file=), which the service reads beside =opencode.jsonc=, whose settings win, and reloads as it changes. The file is written again as the cheap model changes, and deleted once no cheap model resolves or the mode is turned off, OpenCode then titling sessions as it does by default; a file holding anything else is left alone, which is said once. A title the cheap model fails to write is written by the session's own model, as OpenCode does. Each host names its own.

** Prompt caches

A session whose provider still holds its prompt cache, so that its next turn costs less if sent before the cache expires, shows how much of the cache's lifetime is left: in columns, as a short bar and the time left, such as =4m=, text you may copy; in two lines, as a line under its line, drawn from the left and shrinking as the cache runs out. Both take the colour of =opencode-cache-bar=, which inherits =success=, the rest of the short bar =opencode-cache-trough=: the short bar fills with it, and the line is underlined in it, so that both show over the highlight of the current line and the region, which set only a background. Its tooltip tells how the cache stands as you read it, such as =Prompt cache: expires in 4m (1h window), 120k of 130k tokens cached=: the window is how long the provider keeps it after each turn, and the tokens what share of the conversation the next turn reads from it. An expired or unknown cache shows nothing, and neither does a subagent's: you write to its parent, never to it, so only the parent's cache tells what your next turn costs. While the list is shown and a cache is live, a timer redraws the caches alone, every =drover-list-cache-interval= seconds.

** Animated icons

The icons of Working and Retrying sessions are animated in the list, as in opencode.el's mode line, the same frame at the same time: each shows the frames of =opencode-session-status-animations= in turn, by default the eight phases of the moon and a clock whose hand turns (Nerd Font icons, any string will do). Each frame differs little from the one before, so they move rather than blink: a lone solid frame among outlined ones, such as a full hourglass, would read as a blink. Every frame takes the room of the widest, so nothing after it moves in the proportional font. As for the bars of prompt caches, a timer changes only how those few characters display, every =opencode-session-status-animation-interval= seconds, 0.15 by default (a moon cycle in 1.2 seconds), and only while a shown list animates something; =nil= keeps the icons still.

While Emacs has no focus, as when you work in another application with a list in sight, the icons keep moving, slower: every =opencode-session-status-animation-unfocused-interval= seconds, 1.35 by default, which opencode.el's mode lines follow too (formerly =drover-list-animation-unfocused-interval=). They still show the frame of the time, the same in every list and mode line, so a tick spans a whole number of frames, chosen so that every animation shows its next frame: nine frames of 0.15 s, where the moon has eight phases and the clock four hours, and a value of 1 rounds up to those nine too, since seven would show the moon its phase before, turning backwards. Once Emacs has focus again, they show the frame of the time at once and move at the full pace. Set it to =nil= to keep them still while Emacs has no focus. Another frame of Emacs having focus counts as Emacs having it: a list in a frame of its own, on another screen, moves at the full pace while you work in another frame. A list in an iconified frame does not move at all. The bars of prompt caches and the ages keep their pace without focus, as they cost little: every =drover-list-cache-interval= and =drover-list-age-interval= seconds.

** The order of last activity

Sorted by last activity, a session running a turn, working or retrying, is active now, whatever event of its turn came last: running sessions come before the others, and among themselves in the order their turns started, which the events of a turn do not change. So sessions working together keep their places, rather than taking the first one in turn at every step of their turns, many times a second. A session moves when its status does: a turn starting puts it on top, a turn ending or a question puts it first among those not running. A subagent starting under its running parent moves neither its parent nor its tree, and subagents are ordered alike under their parent. The Age column of a running session tells its last event, a few seconds ago, as it is active now.

The others come in the order of their last activity, the time the Age column counts from: the end of their turn, the question they ask, their last event. A session moves only once its activity moved more than =drover-sort-activity-tolerance= seconds, a minute by default, from where it was placed: reading a finished turn, which takes its session from Done to Idle, or a rename moves no session by a few seconds. Sessions whose activity is within a minute of one another keep their order, unless one of them moves by more than a minute: that one moves, wherever the others are. A running session of a front end that does not tell when its turn started is placed at its last event, held alike. Both lists show the same order, whether drawn whole or following changes. Set the tolerance to nil to sort by the exact times.

Ascending, oldest first, the running sessions come last. The order of urgency among sessions of one status, and the groups of last activity, a running session being active today, follow the same times.

Archived sessions leave the list, the mode-line count and every session picker. The view key ~=z~ shows them in the list too, dimmed, after =opencode-archived-icon= (=nf-md-archive=), whose tooltip tells how long ago they were archived; grouped by status, they gather in a group of their own, Archived, last, whose heading counts them, and they never count as needing you. They are fetched when shown, without waiting, and again by =g=; =z= restores those selected, or the one at point.

Sending a prompt to an archived session restores it first, from the prompt (=C-' RET=, whose picker offers a session drover archived while its buffer is still open), as a scheduled prompt goes, or once the turn it waited for ends: drover restores what it archived itself, opencode.el the OpenCode sessions it archived, then the prompt goes. A session that cannot be restored is sent nothing, and one line says why, such as =Could not restore Fix the login redirect from the archive: …=; the prompt stays, or the scheduled prompt fails. Restored, a session leaves the archived ones at once.

| agent-shell     | once no turn runs: the shell runs the agent, which closing it shuts down                                      | the input typed, the prompts queued, the prompt composed in its viewport    |

An OpenCode session's buffer closes once the service confirmed the archive; the report says =Archived Fix the login redirect=, and closing tells only what it kept, =Archived Fix the login redirect; its unsent input is in the kill ring=. An archive the service refuses leaves the buffer as it was and says why on one line, as a warning, =Could not archive Fix the login redirect: PATCH /api/session/… failed (HTTP 409): …; its buffer stays open=. Once its shell or terminal closed, an archived agent-shell or claude-code-ide session is restored as the closed conversation its agent recorded (see [[*Closed conversations][Closed conversations]]); restored before its turn ended, it keeps its buffer.

** Wrapping sessions up

A session you are done with leaves things behind: worktrees it added, folders of notes it wrote while investigating, a second clone of a repository. =Z= (=drover-wrap-up=) tells its agent that you are closing it, so that it cleans up after itself, then archives it and closes its buffer, as =z= would. The prompt (=drover-wrap-up-prompt=) asks it to remove the worktrees it added, the directories it made outside existing repositories and the duplicate clones, and new files that belong to no repository nor existing Org file; to keep work committed or meant to be, edits to existing files and notes added to Org files; to leave alone the temporary folder its harness made for it and the system's temporary directories; and to delete nothing it is not sure it created. It goes as a scheduled prompt goes, out of every window, never over a draft, once the session's running turn, if any, ended, and with the engine's build agent (=drover-wrap-up-agent=), since a plan agent asks before deleting anything. =drover-wrap-up-removal-advice= adds how agents remove files on your machine, when it differs from what they would do, such as a recursive =rm= your rules deny.

The prompt ends with what drover attributes to the session, a hint for the agent, never a list drover deletes: the worktrees added to its repository since it started (neither locked, nor a task's, nor one where another session runs), the directories holding only files its edits created, and the other files its edits created outside any repository, as its engine recorded them: Claude Code and Codex record them, OpenCode only the files of its own working tree. Files made by commands, a clone or a =mkdir=, the agent knows from its own conversation.

Once the session took the prompt, it is archived. An OpenCode session's buffer closes once the service confirmed the archive, its cleanup going on in the service; a terminal's or a shell's stays until the cleanup's turn ended, as closing it would end it. The agent keeps the session open when it needs your decision first: by asking with its question tool or waiting for a permission, at once; by making =DROVER-KEEP-OPEN= (=drover-wrap-up-keyword=) the first line of its last message, followed by what needs deciding; or by ending that message with a question. A cleanup failing or interrupted, or whose last message cannot be read after a few tries, keeps it open too. Kept open, the session is restored from the archive, its buffer kept, and a warning says why, such as =Fix the login redirect stays open: the agent asks: the branch fix-login is not merged: delete it?=; otherwise =Wrapped up Fix the login redirect=. Restored meanwhile, by =z= or a prompt, a session is no longer wrapped up. A session waiting for your answer, a subagent, or one whose conversation is not known yet, cannot be wrapped up; a closed conversation is resumed for it, as a scheduled prompt resumes one.

Another host's session is wrapped up by that host, whose drover tells this one how it ended, and greys =Z= out when it runs a drover that does not. Wrap-ups under way are kept in =wrap-ups.eld= of =drover-state-directory=: after Emacs restarts, an OpenCode session's cleanup is followed to its end, whereas a terminal's or a shell's ended with Emacs, which is told, the session staying archived.

** Selecting sessions

An active region selects the rows of sessions it touches, those shown, which the list highlights: set the mark on a session's line and move a line down, and both sessions are selected, wherever on their lines the region begins and ends. A region running from one group into another selects the rows it touches in both. A group's heading selects nothing, and neither do the sessions of a collapsed group, which do not show: =C-SPC= on the heading of Done selects no session, and a region from it to the next group's heading selects only the rows between that show. A region of some text within one session's lines selects nothing, and shows as a region does in other buffers, to be copied; a region selecting nothing leaves the commands to act on the session at point. The region and what it selects survive the redraws a working session causes.

- =s=, =K=, =z=, =Z= and =x= act on every session selected (see [[*Session keys][Session keys]]), from the list or from =C-'=, whose List group then tells how many are selected; acting ends the selection.
- =M-w= copies the Org links of the sessions selected, one per line, else that of the session at point; a session no link type stores is copied by its title, and a region selecting no session is copied as text.
- =C-' "= quotes them in the prompt (see [[*The prompt][The prompt]]).

* Searching sessions

=C-' S= (=drover-search=) reads a text in the minibuffer and offers the sessions matching it as you type: those the list shows, in the list's order, its groups as the completion UI's groups, each with its status, harness, project and branch, host, age, and why it has its status. A session matches when every word typed, in any order and any case, is in its title, summary, project or branch, or in the first and last prompts of a Claude Code conversation, the first of a Codex one; a subagent the list hides shows when it matches and its parent does not. Matching costs about a millisecond a key over 2,500 sessions.

Once you pause (=drover-search-delay=, a quarter of a second) with three characters typed or more (=drover-search-text-minimum=), the backends that can search what was said in their conversations search it in the background, the search before stopped as you type on: Claude Code's transcripts and Codex's rollouts, with [[https://github.com/BurntSushi/ripgrep][ripgrep]] (=drover-transcript-ripgrep=), in the prompts and replies only, not tool calls, their results nor the requests the CLI records, and OpenCode's sessions through the service's own search (opencode.el's =opencode-search=, with a service of the fork that has it, 2.2.5 or later; an older one is silently left out), there by words rather than as a phrase. The sessions found join those offered, a snippet of the match beside them, the text typed as a phrase, its words across any blanks; =[3 in text]= before the input tells how many, and how many matched sessions out of scope. At most =drover-search-text-limit= matches, 200, are taken. Without ripgrep, which is told once, the search matches what sessions tell and their prompts.

| Key   | In the minibuffer                                                              |
|-------+--------------------------------------------------------------------------------|
| =RET= | open the session chosen, as =RET= in the list; with =C-u S=, in another window |
| =C-l= | show its row in the list, a group collapsed around it expanded                 |
| =C-'= | leave for the menu of what the search searches, keeping what you typed         |

The menu =C-'= opens holds the view keys that scope the search, those of the list's menu on the same keys, since the list shares them: the filter (~=p~ project, ~=s~ status, ~=a~ agent, ~=m~ model, ~=v~ provider, ~=H~ harness, ~=h~ host, ~=d~ since, ~=f~ text, ~=c~ clear), with the subagents, older and archived sessions shown (~=u~, ~=O~, ~=z~), the Field table of the list's menu, its filters alone; each shows its value, and changing one leaves the menu open, the list following. The key you bind =drover-dispatch= to opens that menu from the minibuffer too, whatever it is. =RET=, or the key that opened the menu again, searches again with what you typed, in the new scope, which the prompt names, such as =Search sessions (project drover, +subagents, +older):=. Opening a conversation found in what was said resumes it as =RET= in the list does, at its end: no front end shows a position yet.

The candidates work with any completion UI, Vertico, Icomplete or the =*Completions*= buffer: the search matches them with a completion style of its own, =drover-search=, for its category, =drover-session=.

* Closed conversations

Claude Code and Codex record every conversation, whichever front end ran it, in Emacs or not: Claude Code a transcript under =~/.claude/projects/=, Codex a rollout under =~/.codex/sessions/=. =drover-transcript-engines= names the engines whose conversations drover lists, both by default; one that recorded nothing yet is looked for again at each start. Drover lists them from the time it starts (=drover-attention-mode= or a list starting it), whether or not a front end is loaded, as the CLIs' own pickers list them: titled as the CLI titled them, a Claude Code conversation as its desktop app titles it (the title you gave with =/rename=, else the one Claude Code generated, not the kebab-case name it gives a session as you approve its plan), else by the first line of their first prompt, at most 300 characters, however long the prompt, in their directory and branch, with the model and effort of their last turn, by their last activity among the other sessions; Codex's archived ones among the archived sessions, and Claude Code's subagents under their conversation. Their last activity is the time of their newest message, not of the records the CLIs append of their own as a conversation is opened again, nor of the file's change: a conversation of two weeks ago resumed is two weeks old until a new exchange. A conversation a terminal or shell follows is that front end's session, listed once, with its live status, as old as the conversation until a turn there; closed, it is listed again as recorded, in place.

They show as OpenCode's sessions do. A conversation whose last turn ended in a reply you have not seen is done, one whose turn ended in an error of the API failed, its error the summary, until you see it: mark it seen (=drover-mark-seen=), open it, or look at it in a terminal or shell following it; otherwise it is idle, dimmed, in the Idle group when grouped by status: a turn you interrupted or left with =/exit=, one cut in the middle, or one of =claude -p=, an SDK's program or =codex exec=, whose reply went to the program. Only a reply after drover first read an engine's conversations counts: the hundreds of conversations it finds as it starts are idle. What you saw is kept in =seen.eld= of =drover-state-directory=, a time per conversation still recorded. Their model's provider shows as OpenCode shows it, Anthropic or the one Codex names, and so does their context, the prompt of their newest reply against their model's size: the catalog Claude Code caches tells it, else =drover-claude-code-context-limits= and =drover-claude-code-default-context-limit=, a context past it running a million tokens; Codex's counts tell its window. A Claude Code conversation shows its prompt cache, an hour or five minutes after its last request, as Claude Code asked for it; OpenAI tells no lifetime of its cache, so Codex's shows none. A terminal or shell following a conversation shows its provider, context and cache as its transcript tells them.

- =RET= resumes it: in claude-code-ide, =claude --resume ID= in a terminal started in its directory; in agent-shell, a shell of its engine loading it by its identifier. Of the front ends loaded, the one it ran in comes first, as Claude Code's transcript tells it, unless =drover-resume-front-ends= names the ones you prefer, such as =((claude-code agent-shell))=. With none loaded, as after Emacs started, drover loads one installed first, in that order, then claude-code-ide for Claude Code and agent-shell, agent-shell for Codex; with none installed, one line says which to install. One a front end follows opens there. Scheduled prompts and Org links resume alike.
- Its recap and =v= preview come from the end of its transcript or rollout, without resuming it.
- A session =claude agents --json= lists as running, in the background or in another terminal, shows working, or waiting with =claude attach ID= as what it waits for; it is attached to there, not resumed here. Drover runs the command at most every =drover-claude-code-agents-interval= seconds, 30, while a list shows; nil never runs it. Commands such as this one, or =codex archive=, are started by a shell drover starts once (=drover-command-shell=), so that Emacs never waits for a program to start, which security agents on a managed Mac may make last seconds; one taking more than =drover-command-timeout= seconds, 60, is stopped.
- =z= and =x= archive or restore, and delete them, as the table of [[*Archived sessions][Archived sessions]] says; Codex's through its CLI, =drover-codex-program=, when found. =Z= resumes one to wrap it up (see [[*Wrapping sessions up][Wrapping sessions up]]).

Drover reads only what it needs of each file, its head and tail, then what was appended, and looks at the files every =drover-transcript-scan-interval= seconds, in slices that give way to your typing: those of the last day at every look, every file every eighth look. A Claude Code transcript whose generated title lies further back, megabytes behind the tail of a long session, is read whole once, in the same slices, for its title alone; until then it is titled by that kebab-case name. What it read it keeps in =drover-state-directory=, =claude-code-transcripts.eld= and =codex-rollouts.eld=, a cache checked against the files, so that an Emacs starting reads only what changed; a drover that reads them differently, as one updated may, reads them all again once. =drover-claude-code-history-days= and =drover-codex-history-days= move conversations idle longer among the older sessions, shown on demand (the view key ~=O~); nil, the default, lists them all. =drover-codex-include-non-interactive= lists what =codex exec= ran too.

* Reviewing a session's changes

=R= in a list, or =C-' R= from a session's buffer (an OpenCode session's included) or beside a list, opens a review of the changes the session at point made: =*drover review: TITLE*=, a buffer of Magit's sections, a file per section and a hunk per section in it, in diff's faces, in another window than the session's. =TAB= folds a file or a hunk, =n= and =p= move between them, =RET= visits the line at point as the file is now (a line removed, where it was). It shows one of three scopes, =T=, =S= and =W= switching between them, =g= fetching again; =C-u R= asks which, =drover-review-default-scope= (the last turn) choosing otherwise:

| Scope           | Key | What it shows                                                                                                                                       | From                                                                                                                                                                                         |
|-----------------+-----+-----------------------------------------------------------------------------------------------------------------------------------------------------+----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Last turn       | =T= | what the session changed since its newest prompt                                                                                                   | OpenCode: its service's diff of the snapshots it took of the working tree, files Git does not track included; Claude Code: its tools' edits and writes, its subagents' too, as its transcript recorded them; Codex: the patches it applied, as its rollout recorded them |
| Whole session   | =S= | what it changed in all its turns                                                                                                                   | the same, every turn: OpenCode diffs from the first prompt to the newest; Claude Code and Codex show each edit's hunks one after the other, numbered as the file was then                     |
| Working tree    | =W= | the session's directory against the commit it started from: its commits since, listed, what is not committed, and the files Git does not track yet | Git: the commit HEAD was at as the session was created, as the worktree's reflog tells; else where its branch forked from origin's default branch; else HEAD, uncommitted changes alone, said so |

A session of another host is reviewed through its host, which computes its changes with its own backends and Git and sends them, 2 MB of patches at most, the files past that with their counts alone; a host running an older drover sends none, which the review says. A session whose engine records no changes, such as Gemini CLI's, shows its working tree. A diff of thousands of lines shows its first screens at once and the rest in slices of a few milliseconds, without stopping Emacs; =M= shows the working tree in Magit, which stages and discards hunks, and =P= the review as one patch in =diff-mode=.

=c= on a line of a diff writes a comment on it, in a buffer below (=C-c C-c= keeps it, =C-c C-k= leaves it); with a region, on its lines, of one hunk. The comment shows under its last line, marked in the fringe; =c= there edits it, =k= removes it, and =C= writes a note on the whole review. Comments are kept per conversation in =review.eld= of =drover-state-directory=, across Emacs sessions and scopes: a comment shows where its lines are, numbered and reading the same, else where they read the same, else at the end of the review, under the lines it quotes. =C-c C-c= sends them: it composes one prompt of the comments not sent yet and the note, and puts it in =*drover*=, set to go to the session reviewed, to be read and edited before =C-' RET= sends it; with a prefix argument, =C-u C-c C-c=, it is sent at once. Comments sent stay dimmed, marked with when, for =drover-review-sent-days= days (7), and leave the next prompt; editing one makes it pending again. =C-c C-k= discards the comments not sent. The prompt groups them by file, each telling its lines, on the new side of the diff, or of the file before the change for lines removed, and quoting them under their hunk's heading:

#+begin_example
  Review of your changes in the last turn: 2 comments on 2 files.

  `src/auth/login.go`:
  - Line 42:
    ,#+begin_src diff
    @@ -38,6 +38,9 @@ func Login(w http.ResponseWriter, r *http.Request) {
    +	next := r.URL.Query().Get("next")
    ,#+end_src
    Check that next is a path of this site, not another host.

Sent, its blocks are Markdown fences, as every prompt's.

* Usage

=C-' $= (=drover-usage=) shows in =*drover usage*= what agents cost: the tokens they used, input, output, read from and written into prompt caches, and what those cost, today, this week, this month or ever, grouped by session (its subagents' usage with it), project, harness, provider, model, host or day, each group broken down by another, then where each cost comes from. =V= there opens its menu, on the families of keys of the list's: ~=d~ the period, ~=g~ the grouping, ~=b~ what each group is broken down by, ~=o~ the order, ~=p~, ~=H~, ~=h~, ~=m~ and ~=v~ total one project, harness, host, model or provider, ~=c~ all of them again; =g= reads anew what changed, =RET= on a session opens it. The list shows each session's cost, its subagents' included, in the column =cost= (=-$= in the View menu hides it); this report tells its tokens. =drover-usage-mode-line-mode= shows today's cost in the mode line, its tooltip by harness.

Each engine's usage comes from what it records:

| Engine      | Tokens                                                                                   | Cost                                                                    |
|-------------+------------------------------------------------------------------------------------------+-------------------------------------------------------------------------|
| OpenCode    | each step its service records in its database (=drover-opencode-database=), read only     | as its service recorded it, at its catalog's prices                     |
| Claude Code | the usage of each reply of its transcripts, a reply recorded twice, as by a fork, once    | priced: =drover-usage-prices=, then OpenCode's catalog, then drover's own |
| Codex       | the tokens of each request of its rollouts, its cached input apart                       | priced as Claude Code's                                                 |

A subscription paying for usage includes it (=drover-usage-billing=): Claude Code logged in to an account without an API key nor a gateway of its own, Codex logged in through ChatGPT, OpenCode logged in to a provider's subscription, such as ChatGPT's, as its service tells (=drover-cheap-signed-in=). GitHub Copilot through OpenCode is priced, though OpenCode logs in to it: since June 2026 Copilot bills each token at its model's list price, drawn from the plan's monthly AI credits, and OpenCode records that cost. Included usage shows its tokens, and what it would have cost at list prices, priced as Claude Code's and Codex's tokens are, in green (=drover-usage-included=): money it did not cost, what the subscription is worth, =$3.10 included=, =$3.10= in a column; a total of both reads =$12.40 + $3.10 included=, =$12.40+$3.10= in a column, the second in green; =included= alone when no price is known. * The prompt

=C-' "= (=drover-prompt-dwim=) opens =*drover*=, an Org buffer, with a link to the line at point and the region quoted in a code block, an Org heading's line as any other; called again from elsewhere, it adds that context where you left point in the prompt. =C-' N= (=drover-prompt-org-task=) starts a planning prompt for the Org task point is in, from anywhere in its entry, folded or narrowed (=drover-prompt-task-format=, =drover-prompt-task-agent=), asking before it replaces a draft. =C-' '= (=drover-prompt-toggle=) shows or hides the prompt.

In drover's own lists, =*drover sessions*= and the sidebar, =C-' "= quotes the sessions selected, or the one at point, for an agent to read: an item per session, its Org link, titled after it, how it stands, and its last reply in a Markdown block, cut to =drover-prompt-quote-reply-lines= lines and =drover-prompt-quote-reply-characters= characters with a note telling how much is left out. Everywhere else, a session's buffer and the lists of other front ends included, it quotes the line at point or the region, whatever session is at point; from a session's own buffer, it says the text comes from that session, by its Org link, rather than from a line of the buffer. The replies are fetched from the backends all at once, the echo area counting them as they arrive; a backend not answering within =drover-prompt-quote-timeout= seconds leaves its session quoted without one:

#+begin_example
  Agent sessions:
  - [[agent-session:opencode/ses_1][Fix the login redirect]] — done
    Last reply:
    ,#+begin_src markdown
    The redirect now keeps the page users came from.
    ,#+end_src
  - [[agent-session:opencode/ses_2][Bump the SDK]] — waiting for an answer: asks: Which version?
#+end_example

The header line shows what the prompt would run: directory, agent, model and effort, dim when inherited from the engine's defaults, bold when chosen with =C-' d=, =a=, =m= and =e=. From another buffer these keys choose for the next prompt. =a= switches directly when only two agents are offered. A new OpenCode session starts on the model you last chose for a session, in the prompt or in opencode.el (=opencode-last-model=), not on the model of the session you last wrote to: replies and scheduled prompts choose nothing. A last choice whose provider the catalog no longer lists, as while it is down, gives way to the service's default model until it is back.

=C-' RET= sends: it asks for the target among the running sessions, then the new sessions of =drover-prompt-new-targets=, each labelled with what it would run; in that picker =C-'= changes the options. It sends from any buffer as from the prompt, the prompt shown or not, while =*drover*= holds more than blanks; from drover's list, =C-' M-RET= sends, as =RET= opens there (see [[*The List group][The List group]]). Explicit choices are applied to the target before the prompt goes out. With an active region, only the region is sent and the rest stays for another send. A send that sends nothing, cancelled by a check, leaves the prompt as it was. Once a prompt went, to a running session or a new one, here or on another host, =drover-prompt-sent-functions= are called with the session, its buffer here, if any, and whether the send started it, after the command, the prompt's window gone and a new session shown: to bury the session's buffer, for one. =C-' k= clears the text and closes the prompt's window, as =C-' '= hides it, keeping the buffer and the choices for the next prompt; =C-' i= attaches a buffer, quoted, or a project file, linked.

=RET= anywhere in the transcript of an OpenCode session buffer, on an earlier prompt, the agent's text or a block's summary, but on a link, sends nothing: it quotes the line at point, or the region, in =*drover*=, as =C-' "= does there, but as the transcript shows it, without the blocks a collapsed group hides. Drover sets opencode.el's =opencode-old-input-function= to =drover-opencode-quote-old-input= unless you set it yourself; set it to =opencode-put-old-input= to put the line or region in the session's own input, as opencode.el does alone (=C-c RET= there puts the whole prompt in the input whatever the option).

A prompt withdrawn from an OpenCode session (=E=, see [[*Session keys][Session keys]]) goes into =*drover*= to be edited, whole, and its session becomes where the prompt goes, which the header names (=to [Fix the login redirect]=), so that =C-' RET=, or =C-' S-RET=, takes it there without the picker; the header then shows the model and effort that session runs, not a new session's. A prompt being written stays, the withdrawn one following it after a blank line, which the echo area says. The session is forgotten once the prompt is sent, its region included, or cleared, by a click on its name in the header, or by =M-x drover-prompt-forget-target=, and the picker asks again; a session whose buffer closed meanwhile is forgotten as the prompt is sent, and the picker asks. Its attachments go along, files, subagents and skills, each on its label, in the face =drover-prompt-attachment=: sent to an OpenCode session, the prompt carries them again; to a session of another front end, their labels go as text, which a warning tells. Deleting a label whole drops its attachment. A prompt holding attachments cannot be scheduled, as a scheduled prompt is text. Other front ends can do the same through =drover-prompt-edit-for=.

* Tasks

A task is an Org heading, worked on by agent sessions in a place of its own: a Git worktree on a branch of its own (=worktree=, the default), the main checkout of a repository (=in-place=), or a directory (=folder=), such as a project folder for an investigation.  =C-' n= (=drover-task-start=) on a heading starts its task, or continues it once it works somewhere: one of its sessions opens, or another starts in the same place.  With =C-u=, how it works, on which host and from which base are asked; =C-' N= only writes a prompt for it, as before.

** Starting a task

Starting a task:

- resolves its repository: =DROVER_REPO=, inherited, a repository's name such as =10gen/secateur=, the same on every host (never a path), one asked for among several; else the repository of the Org file; else a folder a file link of its entry names, or =DROVER_FOLDER=; else it asks, and offers to save =DROVER_REPO= on the heading;
- names it after the heading, its Jira key first when it has one (its ID, as ejira makes it, or a =JIRA= property): =RNDSEC-4975-onboard-the-scanner=, accents dropped, cut between words (=drover-task-slug-length=);
- fetches the repository's default branch from origin, within =drover-task-fetch-timeout= seconds and never prompting, and makes the worktree from it, on a branch of that name (prefixed as the repository says), falling back to =HEAD= when origin is out of reach; =C-u= offers =HEAD=, another branch, and carrying the main checkout's uncommitted changes into it;
- locks the worktree (=git worktree lock=, its reason naming the task), copies the ignored files =.worktreeinclude= names, as Claude Code and Codex do (only those Git ignores, on the task's branch too), initializes submodules, and runs the repository's setup visibly in =*drover task: TITLE*=; a failing setup starts no session, and says so;
- writes =DROVER_WORKTREE=, =DROVER_BRANCH=, =DROVER_BASE=, =DROVER_HOST= on the heading, and a note in its LOGBOOK;
- starts a session there, of the prompt's first new session (=drover-task-harness=), its first prompt linking the heading and quoting its body (=drover-task-prompt-function=).

** How a repository works

How a task's repository works is the repository's to say, never your configuration's: how finished work lands, where its worktrees go when it says, the setup of a new worktree and the checks before a push.  Drover reads it from the repository as a task starts (=drover-repo.el=): its AGENTS.md and CLAUDE.md, read by the host's cheap model, which reports what they prescribe with the line each item comes from quoted, an item whose quote is not in the text, or a command neither the text nor the repository's files name, dropped, so that nothing is invented; and its conventional files, the scripts of =package.json=, the targets of a Makefile, the recipes of a justfile, =pyproject.toml=, =go.mod=, =Cargo.toml= and the lockfiles, whose checks and setup are taken when the instructions name none.  The first time, or once the instructions changed, it shows what it read, each with its source, to accept, or to change for the task, which writes the heading's =DROVER_= properties.  What was read is kept in =repo-facts.eld= of =drover-state-directory=, a cache by repository and by the content of what was read: it can be deleted at any time.

A heading's properties, inherited, override it for its tasks: =DROVER_FINISH= (=merge-push=, =merge=, =pr= or =none=), =DROVER_WORKTREES= (=sibling=, beside the checkout as =CHECKOUT-TOPIC=, or =default=), =DROVER_SETUP=, =DROVER_CHECKS= and =DROVER_TEARDOWN= (shell commands joined by =&&=), =DROVER_TARGET= (the branch work lands on, the default branch otherwise).  A task of another host is read there, the heading's overrides sent with the request.

** What drover writes on headings

What drover writes on a heading is properties beginning with =DROVER_= and notes in its LOGBOOK, never anything else: not ejira's properties, the title, the TODO keyword (but on your word, finishing), the body, nor a child heading, which ejira would take for an issue or a comment.  It saves the file when it had no unsaved change, as a change ejira counts but does not review.  A copy of a task file in a linked worktree, such as a repository's tracked =todo.org=, and the files of =drover-task-refused-files=, are never read nor written.

** Finishing a task

=C-' F= (=drover-task-finish=), on the heading or on one of its sessions, finishes it as its repository says (see [[*How a repository works][How a repository works]]): =merge=, its branch merged into the target in the main checkout; =merge-push=, merged there, checked with the repository's checks, and pushed, a failing check pushing nothing; =pr=, its branch pushed and a pull request opened with =gh=, people merging it, the task cleaned up when finished again once it is merged.  Conflicts are looked for first (=git merge-tree=), and stop it.  Then it cleans up: a snapshot of the worktree kept as =refs/drover/snapshots/BRANCH= (its uncommitted files too, through a temporary index), its =DROVER_TEARDOWN= run, the worktree unlocked and removed, never forced but once you agreed to lose what it names, its branch deleted only once merged, its sessions archived, the =DROVER_= properties of its worktree removed and a note telling what was done, and the heading marked done if you said so, the normal Org way: for a heading ejira syncs, its review then offers the issue's transition.  =C-' W= (=drover-task-sweep=) lists the worktrees of your repositories that may go, those whose directory is gone, such as agents' worktrees in the temporary directory, those of tasks done, and the others with their task, deleting nothing.

** Sessions of tasks, and projects

Drover keeps no index of tasks: a heading is found by its ID alone, also by =ORIG_ID=, the ID ejira replaced with the issue's key, and read when needed, what was read kept in memory until its buffer changes.  A session serves a task when its first prompt links the heading, as tasks start them and =C-' N= did (the conversations Claude Code and Codex recorded, and OpenCode's database, tell first prompts), when it runs in a worktree a task made, which its Git directory tells, or when you linked it with =C-' I=, the one thing drover keeps of tasks.  =drover-task-mode= shows them in the lists: the Project column shows the task's project, its Org category (the file's name, or =#+CATEGORY:= and =:CATEGORY:=), in its colour, after a pill (=drover-project-icon=) that two lines and the sidebar show alone, lined up at the end of the line; =V= groups sessions by task (=g task=) and filters them by project (=p=).  Each project has a colour of the theme in force, those its standard faces show first, Font Lock's and ANSI's, then the others its settings name, readable over its background and apart from one another; more are made in the theme's lightness when projects outnumber them.  A project keeps its place in that palette once given, kept in =drover-state-directory=, so that another theme colours each project anew without reshuffling them.

A task belongs to the host running its sessions, =DROVER_HOST=: =C-u C-' n= starts it on another host, which makes its worktree in its own checkout and starts its session there, and finishing it is that host's (see [[*Other hosts][Other hosts]]).

** Setting tasks up

=drover-task-repositories= names the repositories tasks work in, by the name =DROVER_REPO= gives them, with your own preferences alone: their checkout on each host, the prefix of your branches, whether tasks work in place, where you want their worktrees; how they work is theirs to say (see [[*How a repository works][How a repository works]]).  =drover-task-mode= has the lists show tasks; =drover-start-hook= turns it on as drover starts.

#+begin_src elisp
(use-package drover-task
  :hook (drover-start . drover-task-mode)
  :custom
  (drover-task-repositories
   '(("10gen/secateur" :checkout "~/local/projects/pr-bot/secateur/")
     ("10gen/aegis-security" :checkout "~/local/source/mdb/10gen/aegis-security/"
      :branch-prefix "val.leon/"))))
#+end_src

* Goals

A goal keeps a session going until a condition holds, so that you need not run the checks after each turn and paste the failures back.  =G= on a session, in a list or its buffer, or on a task's heading (=drover-goal=) sets one, or acts on the one it has: pause, resume, stop, or show its log; in the menu, =C-' G= acts on the heading at point in Org, else on the session at point.

- A *check goal*: drover runs the repository's checks itself, in the session's worktree, on this host, after each turn (=drover-command-run=, never waiting; =drover-goal-check-timeout=, 600 s, each), and when they fail sends the agent the failing lines and the end of the output, within =drover-goal-feedback-limit= (8 KB), until they pass.  The checks are those the repository tells agents to run, else those of its conventional files (see [[*How a repository works][How a repository works]]), or the heading's =DROVER_GOAL_CHECKS= (commands joined by =&&=), shown with their sources to confirm or edit before anything runs, and kept on the heading if you say so; a setup the repository needs runs once first.  On a fresh worktree, the checks run once before the next turn, the baseline: checks that cannot run here (a command not found, out of time) arm nothing, and failures already there go with the goal's statement.  An idle session gets the prompt you give with the goal's statement, or the checks run at once; one at work, its turn's end.
- A *criterion goal*: the harness's own goal judges a condition in words (OpenCode's =/goal=, run as the session's own command), which drover follows: bounded in rounds (=drover-goal-rounds=, 15) and money, and checked with the repository's checks when the harness says it is done, their failures setting the goal again.  Harnesses without a goal of their own take none.

A goal stops when it is met; at its limits, =drover-goal-iterations= follow-ups (5), =drover-goal-minutes= (60), =drover-goal-budget= dollars billed since it began (10; what subscriptions include costs nothing, see [[*Usage][Usage]]); when it makes no progress, the same failure twice or a turn changing nothing in the worktree.  It pauses on a turn failing, a reply ending in a question (its last line, or, a little before, as the cheap model tells: =drover-goal-ask-questions=), and protected files edited, tests, snapshots, CI configuration, scripts and lockfiles (=drover-goal-protected=), which it shows, even when the checks pass: resuming accepts them.  A question or a permission the agent waits on is yours; the goal waits for the turn after.  Follow-ups go through the queue of scheduled prompts, out of every window, so that a draft is never touched.

Goals are kept in =goals.eld= of =drover-state-directory=, saved before they run, and come back paused after Emacs restarts; each logs its iterations in =goals/=, bounded (=drover-goal-log-limit=).  =drover-goal-mode= shows them, turned on as a goal is set, and as drover starts while one is not over: the list's Goal column (=-g= in the View menu) shows a goal's glyph (=drover-goal-glyph=), the follow-ups sent of their limit and how it stands, the mode line counts goals running and those met, paused or given up that you have not seen, and the heading of a goal's task gets a LOGBOOK note as it ends.  =M-x drover-goal-list=, or a click on the mode line's count, lists them: =RET= shows a log, =o= opens a session, =p= pauses or resumes, =k= stops.  A session of another host is that host's: its goals run there.

* Fan-outs

A fan-out gives one task to several agents at once, to see what each makes of it: models of several families, one model through two providers, harnesses, efforts, agents.  =C-' &= (=drover-fanout=) on a task's heading, or on one of its sessions, starts one; on a task that works in several places, or whose fan-out was not kept yet, it shows its attempts compared, and with =C-u= more attempts join its fan-out.

- How the attempts run is asked first: side by side, every attempt at once, or in a ladder, one at a time, each under a goal of the repository's checks (see [[*Goals][Goals]]), the next starting only once one gives up, the ladder ending when one meets its goal.
- While =*drover*= holds a prompt, which prompt the attempts get: the task's heading, as =C-' n= sends it, or drover's prompt, which leaves the prompt as sending it does.
- Then the attempts, 2 to 4, each a harness (an entry of =drover-prompt-new-targets=), a model among those the harness offers, an effort among the model's, and an agent: the picker holds the attempts you chose last for this kind of fan-out (=fanout-choices.eld= in =drover-state-directory=), each with what sessions of its model cost before, to add, edit, remove or start.  Drover chooses no model and limits no cost: what an attempt may cost is told from the usage engines recorded (=drover-usage-estimate=: the median and p75 of what this host's sessions of that model were billed over 30 days, those of the repository when at least 3 ran there, or =included= when a subscription covers its provider), and what it costs shows as it runs, neither ever enforced.
- Then, when the repository names checks, whether each attempt runs under a goal of them, asked once for all, the checks shown to confirm or edit, as goals ask; a ladder's attempts always do.  The goals of attempts have no budget: their limits are follow-ups and time alone.

Each attempt gets a worktree of its own, all from the same base: the first is the task's own, made as =C-' n= makes it (or the worktree the task works in already, which keeps its work and its sessions), the others =BRANCH-2=, =BRANCH-3= and so on, from the first's base, written on the heading as =DROVER_WORKTREE_2=, =DROVER_BRANCH_2=, =DROVER_BASE_2=… with a LOGBOOK note each.  Their setups run one at a time, the repository's, in =*drover task: TITLE #N*=, shown when one fails; each session starts, unshown, once its worktree is set up, sent the same prompt.  Without a goal, the checks run in each worktree as its turns end, two attempts at most at once (=drover-fanout-check-concurrency=).  The list shows the attempts under their task (group by task, ~=g~), the column Attempt (=-#=) telling each session's number and model, its tooltip the whole choice; =C-' F= waits until one is kept.

=*drover attempts: TITLE*= compares them, a section each: where it stands, its checks (its goal's, its own as its turns end, or run with =c=; =C-u c= runs every attempt's), its changes from the base, committed or not, the files no other attempt touched, the tests it added and those it edited or deleted, flagged, the other protected files it changed (=drover-goal-protected=), its time, its cost and what its model cost before, its goal, the summary of its last turn, and where it works.  =RET= opens its session, =R= reviews its worktree (see [[*Reviewing a session's changes][Reviewing a session's changes]]), =d= shows how another attempt's files differ from its, in =diff-mode=, =j= has the host's cheap model summarize how the attempts differ, advisory, the attempts given to it by letters, in a random order, without their models, and told after which is which, =+= adds attempts, =g= reads them anew, and =k= keeps one: it becomes the task's, its branch renamed to the task's, the heading's properties telling it; each other attempt's worktree is kept as a snapshot ref, =refs/drover/snapshots/BRANCH-DATE= (its uncommitted files too, removed by force only once you agreed to lose them), its teardown run, its worktree removed, its branch deleted, its goal stopped and its sessions archived, and a LOGBOOK note tells it all.  The task then finishes as any (=C-' F=).

The fan-outs are kept in =fanouts.eld= of =drover-state-directory=, those whose attempt was not kept and the newest 100 kept, and =drover-fanout-mode= follows them, turned on as a fan-out starts, and as drover starts while one has no attempt kept; a ladder whose goal ends while drover is not loaded goes on as the goal ends, through the goal's own record.  Tasks of other hosts are not fanned out.

* Org links

=org-store-link= (=C-c l=) stores a link to the session of the current buffer, whichever front end shows it, or to the session at point in the list, once its engine knows the conversation's identifier: =[[agent-session:opencode/ses_1][Fix the login redirect]]=, =agent-session:ENGINE/ID=, ENGINE the engine (=opencode=, =claude-code=, =codex=), ID the engine's own identifier, which survives the buffer and Emacs. The list's copy (=M-w=) copies the same links. A link is described by the buffer's name, or in the list by the session's title. =C-c C-l= completes over the sessions drover knows; exported, a link shows its description.

Following one shows the conversation where drover finds it in a live buffer, in any front end; otherwise it is resumed in a front end able to: Claude Code's in claude-code-ide or agent-shell, OpenCode's in opencode.el or agent-shell, Codex's in agent-shell (=drover-links-front-ends=). With several installed, drover asks which, the one =drover-resume-front-ends= prefers first; =drover-links-ask-front-end= nil takes that one without asking. Front ends resume in the conversation's directory, which its engine tells: Claude Code's transcripts, Codex's rollouts, the OpenCode service; opencode.el opens a session by its identifier alone.

** Link types of front ends

=drover-links-front-end-types= adds link types opening their conversations in one front end, without asking, such as =claude-code-ide:ID= or =agent-shell:ENGINE/ID=, or reading the links of an earlier configuration:

#+begin_src emacs-lisp
  (setopt drover-links-front-end-types
          '(("claude-code" nil claude-code)               ; asks, as agent-session links do
            ("claude-code-ide" claude-code-ide claude-code)
            ("agent-shell" agent-shell claude-code)      ; ID alone is a Claude Code conversation
            ("opencode" opencode opencode)))
#+end_src

A link may name the host a conversation runs on, =agent-session://HOST/ENGINE/ID=; drover reads such links, and refuses to open them for now.

* Scheduled prompts

=C-' S-RET= (=drover-schedule-prompt=) in the prompt asks for a running session, then when, and sends the prompt, or its region, then: with the agent, model and effort chosen in the prompt, applied as a send applies them, the prompt leaving the buffer as a send does. In an OpenCode session buffer it schedules the input, cleared once scheduled; in another session's buffer it reads the prompt. When is read locally, never by a model, what it resolves to showing as you type, and unreadable or past input asked again:

| You type                                      | It means                                                                |
|-----------------------------------------------+-------------------------------------------------------------------------|
| =in 90m=, =in 2 hours=, =in 3d=, =in 1 week=   | after that long; days and weeks keep the time of day across a DST change |
| =tomorrow=, =monday 5pm=, =11/4 2pm=, =tonight= | the next such day, 9:00 when no time is given, =tonight= at 21:00       |
| =5:30pm=, =17:30=, =evening=                     | today, or tomorrow once past                                            |
| =when turn ends=                              | once the session's running turn ends, offered first while one runs     |
| =after LABEL=                                 | after an event your configuration defines (below)                      |

=RET= takes what you typed, never a candidate it completes to. The prompts wait in =scheduled-prompts.eld= of =drover-state-directory=, survive the session's buffer and Emacs, and =drover-schedule-restore= arms them again, run once Emacs started, after your session buffers are restored, such as with =(add-hook 'after-init-hook #'drover-schedule-restore 95)=: those that fell due meanwhile go then; scheduling or listing them arms them too. At delivery, the session's buffer, or its front end resuming the conversation, shows in a new frame (=drover-schedule-display-function=); the prompt is submitted once the session takes it without touching a draft: an empty input box, an idle shell, a loaded OpenCode session. A session archived is restored first (see [[*Archived sessions][Archived sessions]]); one that cannot be fails the prompt, nothing sent. Sent means submitted to the front end, not answered; a submission Emacs stopped in the middle of is kept as interrupted, since whether it went out is not known. =drover-schedule-wait-seconds= (600) bounds the wait.

=C-' #= (=drover-schedule-list=) lists them: =k= cancels one, =r= retries one that failed or sends now one still waiting, =RET= shows it whole.


A peer telling it may schedule prompts for this host's sessions, as the Android client does (=drover-remote.el=, see =doc/remote.org=, The phone, as built): this queue keeps them and delivers them out of every window, and the peer follows the queue, cancels and retries its prompts.
** Events

Your configuration may define events prompts wait for, such as a restart, and tell drover when they happen:

#+begin_src emacs-lisp
  (drover-schedule-define-trigger 'emacs-restart "Emacs restart"
    :request #'my-ask-for-restart     ; returns a key naming what it asked
    :release #'my-withdraw-restart)   ; called with the key once nothing waits
  ;; Once Emacs restarted, or the restart was called off:
  (drover-schedule-fire key)
  (drover-schedule-fire key "dismissed")
#+end_src

=after Emacs restart= is then offered and read; =drover-schedule-waiting-count= tells how many prompts wait for a key. =drover-schedule-former-files= takes in the queue of an earlier configuration once, renaming its file with =.migrated= appended.

* Engines

An engine is the agent program a session runs: =opencode=, =claude-code=, =codex= or =gemini-cli=. Engines, not front ends, know what a new session runs: their models, their startup defaults (read from Claude Code's settings layers, Codex's =config.toml=, OpenCode's catalogs), their agents, and when they last took a prompt, which picks the engine the header shows. Each front end registers the engines it runs, so agent-shell can run any of them while claude-code-ide runs Claude Code only.

The models the prompt offers come from live sessions: the models each agent-shell shell offers, the catalog the Claude Code CLI caches while claude-code-ide runs a session, and OpenCode's own catalog. Drover asks no vendor API and reads no credential. Each model offers its own efforts, never another's: a shell tells the thought levels of the model it runs only, so the others take theirs from what their engine keeps locally, the effort levels of each model in Claude Code's catalog, the reasoning levels Codex's agent lists for each model and its models cache, and are otherwise unknown, which the picker's annotation says (={effort unknown}=) and the effort key tells rather than offering levels the model may not take. A Claude model is one model whatever names it: agent-shell's Claude agent lists aliases, such as =opus= or =default=, which the catalog resolves to the model they stand for, as the CLI does, so the picker shows =Opus 5.5= once, and agent-shell is sent the alias it lists, claude-code-ide the model's identifier. What live sessions offered is remembered on disk, in =models.eld= of =drover-state-directory= (=drover/= in =user-emacs-directory=, or no-littering's =var/drover/=), so the picker offers an engine's models when none of its sessions runs, each annotated with the day a session last offered it ("remembered from 2026-10-29"). A live answer always wins and replaces the models remembered, but for what it does not tell of a model, such as the efforts of a model the shell no longer runs, or the alias a front end takes for it: those the memory keeps, so it learns each model's efforts as you switch models. A picker open while a shell starts shows its models as they come. Set =drover-remember-models= to nil to keep nothing beyond the Emacs session, and =M-x drover-forget-models= forgets what was kept. =drover-claude-code-oauth-catalog= is obsolete and ignored.

Two front ends may show one conversation, such as an OpenCode session open in opencode.el and in agent-shell: drover lists it once, from the front end whose buffer you used last.

* Backends

A backend registers with =drover-register-backend=, giving functions that list its sessions as =drover-session= records and act on them (open, answer, interrupt, archive, unarchive, mark seen, preview, start, rename, delete, fork, compact), tell which of them apply to a session (=:supports=), fetch its older sessions (=:history=), its archived ones (=:archived=), search what was said in them (=:search=), tell more texts a search matches them by (=:search-text=) the recap of a session's last turn (=:recap=, see =drover-recap=), and, for sessions running elsewhere, the changes they made (=:review=, see =drover-review-fetch=); a backend listing conversations as their engine recorded them says so (=:recorded=), and yields to a front end following one. It reports changes with =drover-backend-changed=, naming the session when it can: with =:session=, a function returning the record of one session, drover then asks for that record alone rather than for every session, and lists draw that session alone. Drover archives the sessions of a backend without =:archive= itself. A backend whose archive, restore, interrupt, marking seen or deletion is answered later says so (=:archive-confirms=, =:unarchive-confirms=, =:interrupt-confirms=, =:mark-seen-confirms=, =:delete-confirms=): acting on several sessions, drover then keeps a few of them in flight at once. A record names its engine and the engine's identifier of the conversation (=engine=, =engine-id=), whether and when it was archived (=archived=), and may tell when the session's prompt cache expires, how long it lasts and how much of the prompt it holds (=cache-expires=, =cache-ttl=, =cache-tokens=, =cache-prompt-tokens=), and what the session runs: its agent as lists show it, in its faces (=agent-display=), its model, compact, its effort and whether that is the model's default (=model=, =effort=, =effort-default=), its provider (=provider=, a compact display such as an icon, and =provider-name=), and its context (=context-tokens=, =context-limit=, =context-tier=, and =context-estimated= when the size is the service's estimate after a compaction). What costs a request to know, such as the context, a backend fetches when asked by =:prefetch=, for the sessions a view shows. For the prompt it may offer =:engines=, =:create=, =:check=, =:apply-options=, =:send=, =:options= and =:settable=, for scheduled prompts =:blocker=, =:submit= and =:ready=; an engine registers with =drover-register-engine= and its models with =drover-register-model-source=, and a front end how it resumes an engine's conversations with =drover-register-resumer=; an engine telling where its conversations ran (=:directory=) has Org links, and one telling what its conversations changed (=:changes=) has their turns reviewed. See =doc/design.org=.

A front end also fits its buffers into the keys. A list of sessions sets =drover-session-at-point-function= and turns on =drover-session-keys-mode=; a prompt buffer sets =drover-session-at-point-function= to its own session and declares the prompt actions it implements with =drover-prompt-define=, such as =(drover-prompt-define 'send #'my-send)=.

* Other hosts

=drover-remote-mode= lists the sessions of drover on other machines beside this one's: each host tells the others the sessions its own backends follow, over spyglass (with its channels and =spyglass-reconnect=, a library of its own), through SSH, and never what it learnt from another host. A peer's sessions come under a backend of its own, =remote:NAME=; the list's =host= column names this host in green (=drover-host-local=) and a peer by its label, dimmed, groups by host (this host first) and filters by host from the menu (~=h~, the column =-h=). The sessions of a peer not connected stay listed as last received, dimmed, their glyphs still, the host's cell telling since when it was last heard from (=core 5m=, its tooltip how it stands; in the sidebar, the host's icon alone, in =drover-host-disconnected=, its tooltip telling both), and leave the mode-line count, =drover-next= and =drover-select=. Recaps, previews (=v=), context sizes and reviews of the changes a session made (=R=, see [[*Reviewing a session's changes][Reviewing a session's changes]]) come through the peer. The session keys act on a peer's sessions as on this host's, as far as the access it grants this host allows (=:access=: =read=, =act=, every action but deleting, =full=): marking seen (=s=), archiving and restoring, interrupting, deleting (asked here, naming the session), renaming, answering a pending question or permission (=A=, what it asks fetched from its host, answered here in the minibuffer), and sending it the prompt, which the picker offers among this host's sessions by the buffers showing it here (its mirror, OpenCode buffer or view), else after them; its host performs each through its own backends, and its rows change once its records did. Acting on many goes in a few requests; a peer running an older drover lists its sessions read only, its menus greyed out, saying why. Scheduled prompts stay on the host running the session. Opening a session of a peer (=RET=) whose host runs it in a terminal or a shell (claude-code-ide, agent-shell) mirrors that terminal here, live, through spyglass: typed into as the access allows (=read= watches), sized by the window here while no window shows it there, resuming after a drop; a Claude Code or Codex conversation without one is resumed there first, as =RET= there would, without taking a window there; killing the mirror leaves the session running.  An OpenCode session opens in a full opencode.el buffer, =*OpenCode@core: Title*=, typed into, answered and scrolled as any, talking to the peer's OpenCode service through the peer's drover, which performs every request against its own service with its own password, as the access it grants allows (=read= reads; =act= also sends, answers, archives, but deletes nothing), and relays the service's event stream; this host never holds that password, and the buffer follows its session again as the link comes back.  The session keys act on it there through its host, as on its row.  A peer whose drover relays no OpenCode service, an opencode.el here talking to one service only, or a session of a peer whose drover shares no terminal, show what its host tells of it, read only, its last reply and prompt rendered as OpenCode's buffers render Markdown, a line telling why; opening marks a turn ended unseen seen there. The search of sessions (=S=) searches what was said in a peer's sessions too, there, with its own backends (its transcripts with ripgrep, its OpenCode service's search), those of its sessions the search offers here, as scoped here (filter, older and archived sessions shown): its matches join the others as they come, each with its host, typing on stops it there, and a peer whose drover searches nothing for others is left out silently. =H= in the menu, =drover-clone=, clones the conversation of the session at point to another host, to go on there: a session of this host to a connected peer granting this host =full= access, a peer's session here; the host is asked, then the directory there, the one the peer's =:directories= map, else the same under the home there, offered. The clone is a conversation of that host, which owns it, with the history of the original, which stays as it is; its records name the directory there, and it opens once made, resumed there (through the peer, as =RET= on its row) or here. A Claude Code conversation is its transcript and the directory beside it (subagents, tool results) copied under its identifier, a Codex conversation its rollout; an OpenCode session goes through the services' export and import (the fork's routes), its settled messages and their attachments. What stays behind: the working tree, which the clone finds in the directory chosen as it is; Claude Code's checkpoints of files (=/rewind=), to-do lists and shell snapshots; Codex's state database row, which Codex makes again; OpenCode's subagent sessions and file snapshots (revert). A conversation recorded there already under its identifier is not replaced. The transfer goes in pieces over the link, shown as it goes, =C-g= leaving it to finish in the background; =drover-remote-open-origin= opens the original of a clone this host received. The prompt starts sessions on a peer too, one granting this host =act= or =full= access: its target picker offers, after this host's new sessions, =[New OpenCode session on Core…]= and the like, one for each harness the peer starts; choosing one asks for the directory there (completed on the peer's directories, which it lists by name alone, the prompt's directory mapped by =:directories=, else the same under the home there), and the peer starts the session through its own backend, without a window, hands it the prompt, and the session opens here, an OpenCode session in its full buffer, a terminal or shell mirrored; one that does not start says why, the prompt staying in =*drover*=. =C-u d= in the prompt's menus chooses the host first; =a=, =m= and =e= then offer that host's agents, models and efforts, and the header shows what a session there runs. =C-u += starts a session on a host chosen, without a prompt. A task starts on a peer granting this host =act= or =full= access (=C-u C-' n=, see [[*Tasks][Tasks]]): the peer makes its worktree in its own checkout of the repository, named alike in its =drover-task-repositories=, runs the setup there, and starts its session without a window; finishing it is the peer's too, for one granting =full= access, which merges or opens the pull request and cleans up as its settings say, never prompting: uncommitted changes there are told here, and lost only once you agree here. Links naming another host, =agent-session://core/claude-code/ID=, open it the same way; a link naming this host (=drover-host=, or one of =drover-host-aliases=) opens here.

** Peers

=drover-host-labels= names local and remote hosts for display, independently of their identifiers. Share the same alist between machines so each keeps its label when viewed locally or remotely. A peer's =:label= remains a fallback, then its canonical name.

#+begin_src emacs-lisp
  ;; On Reaver: dial Core through myssh.
  (setq drover-host-labels '(("reaver" . "Reaver") ("core" . "Core") ("adept" . "Pixel"))
        drover-remote-peers
        '(("core" :dial t :program "myssh" :access full)
          ;; A phone: it owns no sessions, and comes and goes.
          ("adept" :viewer t :access full
           :heartbeat (15 . 60) :resume 300)))
  (drover-remote-mode 1)
#+end_src

A peer with =:viewer= owns no sessions, as the Android client: this host serves it its sessions, never subscribes to it, and lists it in no group, column nor filter; =:heartbeat= gives its connections heartbeats of their own, (INTERVAL . TIMEOUT), and =:resume= how long a connection it made waits for it to come back, its mirrors resuming, a phone closing its streams when its application leaves the screen.

** Pushes to a phone

While a phone is not connected, this host pushes it what needs the user, through UnifiedPush: the phone hands it an endpoint, a topic of a push server such as ntfy, and a key; this host posts its own sessions coming to need the user and leaving it, sealed with that key, so that nothing of the conversations reaches the push server in clear.  It holds what is new while the user types in this Emacs (=drover-remote-push-hold=, 120 s, a peer's =:push-hold= first), and pushes nothing while the phone is in front.

#+begin_src emacs-lisp
  (setq drover-remote-push-endpoints '("https://ntfy.example/")
        ;; A token of the push server, never written here.
        drover-remote-push-token '(pass "ntfy/drover-token"))
#+end_src

=M-x drover-remote-push-test= pushes a test to each phone registered; =drover-remote-status= tells how pushes to each stand.

** What a phone changes and starts

A peer may read what was said in a session, Claude Code's or Codex's, from what its engine records: a page from the end at a time, then what is appended as it comes, as entries a phone draws at its own width.  A peer may read a session's agent, model and effort, and what its engine offers, have others applied to it, alone or before a prompt, and list the directories this host's sessions ran in to start one there, as its access allows: the phone's composer and new sessions.

** How they connect

Each host names itself =drover-host=, by default its system's name up to the first dot, downcased. Either host may dial (=:dial=), or both: the connection dialed by the host whose name sorts first is kept, the other closed, its dialer standing by. =M-x drover-remote-status= tells how each peer stands: connected or not, the round trip and clock offset, its sessions, the revision held, whether it takes actions, the last error and when, and the history of its link (dials, streams opened and ended, how SSH exited, greetings, farewells, snapshots and resumptions, errors); a peer whose own connection ended has =drover-remote-grace= seconds to come back before its sessions dim, and is dialed after =drover-remote-fallback-delay= when this host dials it too; =M-x drover-remote-check= runs each SSH command as the connection will, without a prompt, and tells what fails.  A peer this host cannot reach is tried less and less often, up to every five minutes (=drover-remote-backoff=), and at once as the network changes, the machine wakes or =drover-remote-check= is called; the status tells when the next attempt comes, and the history counts failures alike on one line. Nothing of a peer is kept on disk: its sessions come back as it connects.

Drover never lets an error of its own, out of a command, reach Emacs's reporting of timers, processes or hooks, which prints its data whole: it says what failed on one line of the echo area and =*Messages*=, such as =Drover index of sessions: args-out-of-range: Args out of range: #s(drover--index …), 12=, once in =drover-error-interval= seconds (60) for the same error, and goes on. What comes from outside, a title, a prompt pasting a log, a reply, an error a backend tells, is bounded where drover takes it in: a title to its first line and 300 characters. Loading another version of drover into a running Emacs makes anew what the version before made, its index of sessions, lists and indexes of transcripts, with one short message, rather than misread it.

=SPYGLASS_EL= names a checkout of spyglass with its channels and =spyglass-reconnect=, for the remote layer: without one, =make test= skips the tests of the remote layer, which start a second batch Emacs and talk to it through 127.0.0.1.

=DEPS= names the directory holding the dependencies, elpaca's builds directory by default, and =OPENCODE_EL=, =AGENT_SHELL_EL= and =CLAUDE_CODE_IDE_EL= the checkouts of opencode.el, agent-shell and claude-code-ide the backends are built and tested against, such as =make test OPENCODE_EL=../opencode.el= for a worktree of opencode.el: drover draws with its look, so a change to it is tested with drover's. =make bench= compiles a copy of =OPENCODE_EL='s sources, as an installed opencode.el is, so that the look costs what it costs the user. Tests use a fake backend and fake engines, or stub the front ends; they never touch a running Emacs or OpenCode service, nor read the agents' own configuration.


* Agents

=drover-anvil= gives agents, through [[https://github.com/zawatton/anvil.el][Anvil]]'s MCP server in your Emacs, the sessions you have, of every harness and host: they list and read them, start sessions and prompt them, wait for their turns to end, answer their questions, interrupt and archive them.  =drover-anvil-enable= registers the tools with Anvil:

#+begin_src emacs-lisp
  (with-eval-after-load 'anvil
    (require 'drover-anvil)
    (drover-anvil-enable))
#+end_src

| Tool                       | Does                                                                                                         |
|----------------------------+--------------------------------------------------------------------------------------------------------------|
| =drover-sessions=          | Lists the sessions, the most urgent first, filtered by status, harness, project, host and attention          |
| =drover-session=           | Reads one: where it stands, its model, the recap of its last turn, what its pending requests ask             |
| =drover-session-create=    | Starts a session, unseen, with a harness, directory, model, effort, agent and first prompt; returns its key  |
| =drover-session-send=      | Sends a session a prompt, as its front end delivers prompts: OpenCode queues or steers the running turn      |
| =drover-session-wait=      | Waits until a session's turn ends or it needs you, with a timeout; Emacs never waits, the call does          |
| =drover-session-answer=    | Answers a pending question or permission, or dismisses it                                                    |
| =drover-session-interrupt= | Stops a session's running turn                                                                               |
| =drover-session-archive=   | Archives a session                                                                                           |
| =drover-job=               | Returns the answer of a job a tool answered with, for clients that cannot wait                               |

What agents may do is yours to say, =drover-anvil-permissions=, action by action: on any session, on those of the caller's project (its repository, worktrees included), on those the caller started, or never.  By default they read every session and wait on any, start and prompt sessions of their own project, interrupt, archive and answer the questions of the sessions they started, and answer no permission.  The caller is the session whose agent calls, as its client names it (OpenCode does); one not named may do only what applies to any session.  No tool acts on the caller itself, nor on a session whose turn waits for the caller's, nor waits for one waiting for it.  Every call is logged in =anvil.log= of =drover-state-directory= (=drover-anvil-log-file=), and an action that cannot be logged is not taken.  Agents start sessions of the harnesses of =drover-anvil-create-harnesses=, OpenCode's by default, which start without showing.
